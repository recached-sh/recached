## 1. PR #172 (deadline bound): `rc-base` against `rc-pr1`

The change adds checked arithmetic to the expiry forms (`SET` EX/PX/EXAT/PXAT, `SETEX`, `PSETEX`, `EXPIRE*`, `GETEX`). It also adds a cheap check of each AOF record and replicated frame for the two legacy shapes. It does **not** touch `INCR`, `HSET`, a plain `SET`, or the borrowed read and write paths. Counter propagation is unchanged (the counter fix was not shipped: `V0.6O-F-TTL-DESIGN.md`).

AOF writes per command and frame sizes are unchanged: counter frames still say `KEEPTTL`. RSS is unchanged (±0.3 MiB).

**Reading this.**
- **The added work is nil on every measured path**: user instructions per op are identical to ±5.
- **INCR at P=1 is consistently 2–3% slower** (all 5 repetitions, with and without AOF). That comes from 3.7% more user cycles per op for the same instructions, and from more kernel time per op. INCR's executed code did not change. This is a layout or run-condition effect of a rebuilt binary, not added work.
- **INCR at P=16 moved the other way (+1.1%), and SET and HSET are flat.**

The deadline-bound change has no measurable cost of its own. The INCR P=1 difference is recorded, not explained further.

**Allocations.** None added: `deadline_after` is arithmetic. The legacy-record check inspects existing words and allocates only when it rewrites a record, which never happens for a record this build wrote.
