# v0.6.0 Phase 6N-C: targeted reliability

**Rule followed (brief §6):**
- Reuse the 6N-1 production soak for unchanged inline behaviour.
- Do not repeat it because Option D exists.
- Run **one** targeted sustained validation of `coalesced` only if that mode is being considered for deployment or default adoption.

**Outcome:**
- **No soak was run in 6N-C.**
- The default path's 6N-C changes are covered by deterministic tests, CI and the M1 runs. **No sustained run on `0b48332` was made.**
- `coalesced` is **not** being considered for adoption, because it failed M1 and regressed P=16. So its sustained validation was **not run** and remains a precondition of any future adoption.

## Baseline reused: the 6N-1 production soak (default `inline` mode)

[6N-1 production soak](../6n-1/V0.6N-1-PRODUCTION-SOAK.md): one 40-minute run on the same Fedora host, release candidate `e6fcd5b`. 28/28 checks passed or were informational:
- no lost acknowledged write;
- DEDUP exactly once;
- replica convergence;
- QSUB and WATCH correctness;
- no cross-tenant push;
- crash recovery;
- stable memory.

### What that soak does and does not cover now

The soak ran on code **before** the 6N-C fixes. Those fixes changed the *default* (`inline`) path in five places:

| Change on the default path | Exercised by the 6N-1 soak? | Evidence it is reliable |
|---|---|---|
| 0a: TCP DEDUP writes no longer defer their AOF wait | No (the old behaviour ran) | Deterministic `dedup_ack_order` tests and the `always` fail-stop subprocess test; CI; full workspace suite (1294–1301 passed at each integration point) |
| 0c: QSUB waits for the AOF tail before `qstate` | No | `qsub_aof_cut` (all policies, disk-stall liveness, `always` failure); `integration_6nc` |
| 0d: replica DEDUP records striped, `still_following`, log first; full-resync table under the barrier | No | `replication::dedup_order_tests`, existing `replication_dedup` and `replica_6l` suites |
| 0b and #133: WS refusals under the identity stripe, paced; none recorded on a replica | No | `ws_refusal_barrier` (8 tests including SAVE, checkpoint window, replica cut, flood, replica, token expiry) |
| 0e: push receivers counted once routed | No | `ws_fastpath`, `write_gate`, existing `ws_auth` and `sync_routing` |

**Assessment.**
- Each change is small, tested deterministically with mutation checks, and reviewed independently and in combination.
- Under the brief's rule, none of them called for a fresh soak, and none was run: there was no failing interaction.
- The 6N-1 soak therefore remains the sustained evidence for the inline *architecture*. It is not evidence for the exact `0b48332` binary.
- **Before v0.6.0 is released, one soak of the final release candidate in the default mode is still required.** That is a release-gate item, not a 6N-C item.

## `coalesced` mode

| Validation | Done | Result |
|---|---|---|
| Deterministic concurrency tests (`coalesced_fanout`: batching, cancellation, failure contract, end-to-end ordering) | Yes | Pass; mutation-checked |
| The server's in-crate suite in `coalesced` mode, which includes the replication, WS, WATCH, QSUB, DEDUP, fail-stop and torn-write tests | Yes: the CI step added by #134 (green on #134 and on `dev` `0b48332`), and locally (544 passed, 0 failed) | Pass |
| Combined correctness tests in both modes (`integration_6nc`) | Yes | Pass |
| Short functional smoke, native, on the M1 binary | Yes (`fedora-i5-9400f-20261119/smoke/`) | `watermark` is refused; `coalesced` starts and logs `fanout=coalesced`; it shuts down cleanly |
| Replication under load (M1) | Yes: 9 replicated `coalesced` runs of 1M SETs each (P=1, P=16, 4 workers) | Every run converged and its 300-key sample matched the replica. No error lines in any server log. |
| Targeted sustained validation (AOF everysec, a replica, QSUB/WATCH, DEDUP, WS sync, replica reconnect and resync, crash recovery) | **No** | Not run: the mode is not proposed for deployment or default after failing M1 |

### Paths not validated in `coalesced` mode

- **Sustained operation:** memory growth over time, and long-run replica reconnect and resync cycles under load.
- **Crash recovery of a coalesced-mode primary, end to end on the binary.** The in-crate fail-stop subprocess tests do run in that mode, but there is no native kill and restart under load.
- **The binary-spawning harnesses in `server-native/tests/`** (`aof_v06`, `restart`, `redis_diff`, `sync_bench`, `dedup_bench`). They clear the environment, so they run inline only.
- **Capped stores, EXEC-heavy workloads and the replica applier under load.** Review B flagged these as places where the yield gains nothing; no measurement was taken.

## Recommendation

- Keep `RECACHED_AOF_FANOUT=inline` as the default. Do not recommend `coalesced` for production.
- If the coalescer's gain heuristic is fixed and the mode re-measured, the one targeted sustained run above becomes required before any adoption.
- Separately, the v0.6.0 release needs one default-mode soak of its final candidate (see the [release gate](V0.6N-C-RELEASE-GATE.md)).
