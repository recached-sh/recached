# v0.6.0 Phase 6N-C2: Option D, coalesced inline AOF

**Design:** 6N-B Option D ([alternatives](../6n-b/V0.6N-B-ALTERNATIVES.md), [implementation plan](../6n-b/V0.6N-B-IMPLEMENTATION-PLAN.md) PR 1).
**Switch:** `RECACHED_AOF_FANOUT=inline|coalesced`. The default is **`inline`**, and the default is unchanged.
**Not implemented (by scope):** `watermark` mode, commit sequences, watermarks, staged effects, and Option A in any form. `RECACHED_AOF_FANOUT=watermark` is refused at startup.
**Merged:** PR #134 → `dev` `0b48332`. Commits:
- `ccd134d`: the change;
- `20f6177` and `e6fd577`: integration tests;
- `fd92f79`: docs;
- `3531fef`: review fixes.

**Measured:** [Gate M1](V0.6N-C-M1-PERFORMANCE.md). A gain at P=1, a regression at P=16, and M1 = FAIL.

## The change

On the path that cannot defer its AOF wait to its connection, a write used to call `AofWriter::append`. That path covers:
- every write on a primary with replication enabled;
- every replicated write applied on a replica (through `on_write`);
- writes with a WebSocket route candidate, a watcher or a live query, on either transport;
- DEDUP writes (since PR 0a). In `coalesced` mode these keep the plain inline append; see below.

Three kinds of write append inline in *both* modes (review findings F1, F2 and M1):
- **DEDUP-wrapped writes** (`3531fef`). They hold the process-wide `dedup_order` across their append, so no other DEDUP write could join their batch. A yield would only hold everyone else back.
- A WebSocket write that nothing observes. It goes through `append_client_write`, which has no deferral scope on a WebSocket connection and so falls back to `append`.
- DEDUP records that change no data (`log_dedup_outcome`).

None of these is in the M1 workload.

`append` queued the frame and led the batch at once. Each such writer therefore wrote its own frame: 1.00 `write(2)` per command with 50 replicated clients (6N-1 Test B).

In `coalesced` mode, `ServerState::on_write_logged` calls `AofWriter::append_coalesced` there instead:

```text
queue_only(frame)                        -- place in the file fixed now, under the caller's stripes
if on a runtime && coalesce_inline.should_yield():
    holders = strong_count(done)
    guard = LeadOnDrop                   -- cancelled during the yield → lead on drop
    yield_now().await                    -- other ready writers queue into the same open batch
    guard.disarm()
    coalesce_inline.observe(gained = done.is_complete() || strong_count(done) > holders)
lead()                                   -- perform the batch for all, or find it written
gate_wait(done).await                    -- the batch's outcome, exactly as append
```

After it returns, `on_write_logged` fans out to replicas exactly as before. The caller then notifies watchers and live queries, sends the WebSocket push, releases its stripes, and replies.

### What is reused and what is new

| Reused unchanged | New |
|---|---|
| `AofShared`, `AofBatch`, `AofDone`, `lead`/`drain_blocking`, `settle`/`fail_stop`, torn-write cut-back, the `Coalescer` type (its heuristic, back-off and stats), `gate_wait`, replication `fan_out` | `AofFanout` (parse and display), `AofWriter::{set_fanout, fanout, append_coalesced}`, `LeadOnDrop`, a second `Coalescer` instance (`coalesce_inline`) for this path, the `recached_aof_fanout` INFO field |

There are no new tasks, queues, locks, sequence numbers or watermarks. The diff in production code is one enum, one method, one guard, one branch in `on_write_logged`, configuration parsing, and the INFO line.

## Preserved properties

| Property | Why it holds in `coalesced` |
|---|---|
| Fan-out follows the writer's own AOF stage | `append_coalesced` returns only after `gate_wait` on its own batch, which is the same wait as `append`. Replication `fan_out`, watcher and live-query notification and the WS push run after it, on the writer's task. |
| Conflicting writes keep one order everywhere | The writer holds its write-order stripes across the yield. A conflicting writer waits on the stripe, so its frame is queued after, and its fan-out is after too. |
| Replication offsets | Assigned in `fan_out` under the stream lock, in fan-out order, as before. Independent keys were never globally ordered. |
| No reply before its AOF stage | The reply follows `execute_ordered_write`, which follows the append. WS and TCP gates are unchanged. |
| `always` fail-stop | The batch is performed by `drain_blocking`. A failure calls `fail_stop` before any `done` completes, so no coalesced writer resumes. |
| `everysec`/`no` non-fatal failure | Every writer of the failed batch gets `Err`, and `on_write_logged` latches persistence unhealthy, as before. |
| Torn-frame recovery | The same `perform` and `cut_back`. A batch is still a run of whole frames. |
| Liveness | Every writer leads after its yield. A writer cancelled mid-yield leads on drop. Off a runtime it degrades to `append`. The yield is one `yield_now` and is never repeated. |
| Single client | The path's own `Coalescer` (`coalesce_inline`, separate from the TCP gate's since `3531fef`) backs off after 2 yields that gained nothing (`COALESCE_MISSES`), then leads at once for the next 32. **Caveat, measured in M1:** a yield counts as a gain when *another writer performed the batch*, even with almost nothing in it. At P=16 nearly every yield was judged a gain while batches held 1.2 frames, so the back-off never engaged. See [M1](V0.6N-C-M1-PERFORMANCE.md#why-p1-improved-and-p16-regressed). |
| Inert configurations | With no AOF, the mode does nothing. `RECACHED_AOF_COALESCE=off` turns off both `Coalescer`s, so `append_coalesced` is `append`. A write that can defer still defers, and that path is untouched. |
| Lock scope (review M1) | Only tokio stripe guards are held across the yield, and no std guard. Writers that hold *every* stripe (a capped store's evicting writes, EXEC) can yield with nothing to gain. With its own `Coalescer`, the path backs off for those without disturbing the TCP gate's coalescing. |

## What changed for an operator

- `RECACHED_AOF_FANOUT` is documented in `docs/server/configuration.md`. Values: `inline` (default) or `coalesced`. Anything else is refused at startup.
- `INFO persistence` reports `recached_aof_fanout:<mode>` when an AOF is enabled, and the startup log names it.
- **No default changes.** `coalesced` is opt-in under evaluation. **M1 does not support adopting it:** it regresses P=16 throughput and p99. Adopting it would also need the targeted sustained validation (see [reliability](V0.6N-C-TARGETED-RELIABILITY.md)) and a maintainer decision.

## Tests

`server-native/src/tests/coalesced_fanout.rs`:

| Test | Shows |
|---|---|
| `the_mode_parses_strictly_and_defaults_to_inline` | Empty or `inline` → Inline; `coalesced` (any case) → Coalesced; `watermark`, `on`, `1`, `coalesce` and ` inline` are refused |
| `fifty_ready_writers_share_writes_only_when_coalesced` | 50 writers ready on one worker, under `no`, `everysec` and `always`: ≤ 3 batches when coalesced, 50 inline (`no`/`everysec`). No append returns before its frame is in the file. |
| `a_writer_cancelled_mid_yield_strands_nothing` | Polled once and dropped during the yield, under every policy: the frame is still written, with no other traffic |
| `a_failed_batch_fails_every_coalesced_writer_with_its_contract` | `always` fsync failure: every writer gets `Err` and the writer stops. `everysec` write failure: non-fatal, and the writer goes on. |
| `replicated_writes_coalesce_and_keep_their_order` | A real primary write path with replication and an attached replica: 52 concurrent writes share ≤ 6 batches (inline control ≥ 45). Each reaches the AOF and the replica once, and none returns before its frame. A contended key has the same order in the AOF, the replica stream and the store. |

**Mode parity:**
- Test builds open every AOF writer in the mode `RECACHED_AOF_FANOUT` names. The fail-stop subprocess child inherits it.
- CI runs the server's in-crate suite (`--bins`) a second time with `RECACHED_AOF_FANOUT=coalesced`. That covers every in-crate replication, WS, WATCH, QSUB, DEDUP, fail-stop and torn-write test in that mode.
  - The binary-spawning harnesses in `server-native/tests/` clear the environment, so they run inline only (review L2).
  - An unparsable test-mode value fails the run (review L3).
- `tests/integration_6nc.rs` (correctness integration gate, condition I1) runs in both modes.
- `INFO` coverage: `info_persistence_always_reports_loading_zero` asserts the field.

**Native smoke** (`fedora-i5-9400f-20261119/smoke/`, M1 binary):
- `RECACHED_AOF_FANOUT=watermark` is refused at startup with `InvalidInput`.
- `coalesced` starts, names the mode in its startup log (`AOF enabled: … fanout=coalesced`), and shuts down cleanly.
- Every M1 primary log confirms the mode its cell ran in (`fanout=inline` or `fanout=coalesced`).

**Independent reviews:** two, both **APPROVE WITH NITS**, with no correctness, durability, ordering or security defect. Findings and fixes are in [the review summary](V0.6N-C-INDEPENDENT-SECURITY-REVIEW.md#option-d-134).
