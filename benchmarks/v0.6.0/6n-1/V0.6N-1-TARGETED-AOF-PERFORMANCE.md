# v0.6.0 Phase 6N-1: targeted AOF performance (Test A)

**Verdict:**
- Coalescing roughly doubles 1-worker AOF throughput and halves its CPU per op, with a better p99.
- Recached is still at **0.67–0.78× Redis** with 1 worker, below the 90% target.
- The 4-worker coalescing gap reproduces on Linux.

## Answers

**1. Did coalescing substantially improve 1-worker, 50-client AOF throughput? Yes: 1.94×** (64.5k → 125k SET/s).
- INCR improved 1.88× and HSET 1.80×.
- `write(2)` calls fell 10× at P=1 and 10× at P=16.
- This matches the 6M Mac counters (9.5 commands per write), now on Linux.

**2. Did CPU per operation improve? Yes, about 2×:** 11.9 → 5.9 µs per SET.
- It is still **1.45× Redis** (4.08 µs).
- For comparison, the gap without persistence is 1.20× (6L C).

**3. Did p99 regress? No. It improved:**
- 0.86 → 0.54 ms at P=1, 50 clients;
- 2.30 → 1.92 ms at P=16;
- 1.71 → 0.98 ms at 100 clients.

Mean queue wait per batch rose from 0.5 to 23 µs. That is the coalescing yield, and it is well below the latency it saves.

One exception: at 4 workers, P=16, p99 rose from 2.32 to 3.35 ms. Off was very noisy in that cell (29% spread) while on was steady (0.1%), so this is a small regression, flagged but not decisive.

**4. Does the 4-worker issue reproduce on Linux? Yes.**
- Coalescing reaches only 2.2 commands per write at P=1 (1.2 with it off), against 10 at 1 worker.
- At P=16 it reaches 3.5 against 3.3: no gain at all.
- Throughput at P=1 still rose 1.29× (148k → 190k), from fewer and cheaper writes. At P=16 it did not change.

**5. Does Recached reach ≥ 90% of Redis's throughput under comparable AOF conditions? No:**

| 1 worker | On / Redis |
|---|---:|
| SET, P=1 | 0.78 |
| SET, P=16 | 0.75 |
| SET, 100 clients | 0.77 |
| INCR | 0.67 |
| HSET | 0.71 |

With 4 workers Recached exceeds single-threaded Redis (1.19–1.20×), but it uses 3 cores to do it.

## Where the remaining gap is

| | µs CPU/op, SET, P=1, 50 clients |
|---|---:|
| Recached, coalescing on | 5.91 |
| Redis | 4.08 |
| Gap | 1.83 |

Without persistence (6L C, same host, `159d7e9`), Recached's SET costs 1.20× Redis's CPU. AOF everysec therefore adds proportionally more on Recached even after coalescing.

Batches average 10 frames, against Redis's single write per event-loop pass, and Recached pays a scheduler yield per batch. Locating the gap needs `perf` profiles, which are not taken here. No optimization was attempted.
