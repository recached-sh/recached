## The single run (`run-targeted.sh`, `RUN=D`)

It runs the existing 6L harness, `6l/soak/soak.sh`, once, with:

| Setting | Value |
|---|---|
| Binary | The RC binary: `e6fcd5b`, with its sha256 checked |
| Reservations | **off**, the v0.6.0 default |
| Duration | `SOAK_SECS=2400` (40 min) |

**Topology and load** (all from the harness, unchanged):
- primary + replica; AOF everysec; `RECACHED_SECURITY=multitenant`;
- WebSocket sync tenants; QSUB and WATCH routing; DEDUP retries; TTL churn;
- `BGSAVE` every 60 s;
- replica `SIGKILL` and restart every 240 s;
- a live-replica full resync every 300 s;
- at the end: a `SIGKILL` of the primary and recovery from snapshot + AOF.

**Checks (`verdict.txt`):**
- the INCR ledger loses nothing that was acknowledged;
- DEDUP applies each id exactly once;
- compare-and-set accounting;
- replica == primary, both quiesced and after the crash recovery;
- no cross-tenant reads;
- QSUB and WATCH deliveries;
- no `panicked` in the logs;
- RSS trend;
- replica lag p50 and p99.

```sh
RUN=D SOAK_SECS=2400 RC_SHA=e6fcd5bcac3fc15a171ee7800340d77501c4bfc8 RC_BIN=$RC_BIN RC_SHA256=$RC_SHA256 \
  bash benchmarks/v0.6.0/6n-1/run-targeted.sh
```

## Scope note

The primary has a replication listener, so its writes take the immediate per-command AOF append, not the 6M coalescing path. This soak verifies the correctness of the integrated production topology. It says nothing about the coalescing speed-up, which is Test A's job.
