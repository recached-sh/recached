## The three questions

**1. Did Phase 6M materially improve real AOF performance?**

Yes, for standalone 1-worker AOF: 1.94× throughput, half the CPU per op, and a better p99 (dedicated Linux, native, 3 interleaved reps). It did not help:
- the 4-worker case (2.2 commands per write);
- any primary with a replication listener. That path still makes one write per command and runs at 0.45× standalone.

**2. Is the corrected production build reliable under sustained load?**

Yes, for 40 minutes on the integrated topology. All 28 soak checks pass:
- ledger, DEDUP, replica equality before and after the crash recovery, tenant isolation, QSUB and WATCH;
- no deadlocks, no panics;
- RSS steady to within about 4%.

Durability fault handling is proven by CI on the identical source.

**3. What exactly still prevents v0.6.0 from being released?**

Three performance targets, none of them a correctness issue:

| Target | Required | Measured |
|---|---|---|
| AOF throughput | 0.90× Redis | 0.67–0.78× standalone; about 0.33× with replication (54k vs Redis's 160k) |
| Throughput without persistence | 0.90× Redis | 0.70–0.86× on several commands |
| Memory per key | 1.5× Redis | 1.89× |

## Recommendation

The measurements fit both path B and path C. They are complementary, and the maintainer decides the order and scope.

**Path B: Phase 6N-B, watermark-gated AOF fan-out. Design and independent review only.**
- The decision rule's two conditions are met: 1.00 vs 0.10 writes per command, and a 55% penalty.
- The replicated path is what production runs, and it is the largest single gap measured.
- No implementation without approval.

**Path C: a focused CPU and memory milestone.**
- 1.89× memory and the no-persistence throughput gaps fail independently of AOF.
- The remaining standalone AOF gap (5.9 vs 4.1 µs/op) should be profiled first: install `perf` on the host and use the 6M kit's phase F method. No AOF architecture change without that evidence.

The 90% throughput and 1.5× memory targets stay as set; no exception is assumed. **Path D, release, is not met. Nothing was tagged or published.**
