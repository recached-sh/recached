# v0.6.0 Phase 6N-1: replication-enabled AOF profile (Test B)

**Verdict:**
- With a replica connected, the primary makes **one AOF `write(2)` per command**.
- It runs at **0.45× the throughput** of the same primary without a replication listener, at 2.3× the CPU per op.
- That meets the decision rule, so the evidence supports **Phase 6N-B**: watermark-gated AOF fan-out, design and independent review only.

## Method

| | |
|---|---|
| Primary | AOF everysec, 1 worker, CPU 0 |
| `standalone` | No replication listener |
| `replicated` | `RECACHED_REPL_ENABLE=1`, plus one connected replica (1 worker, CPU 2) that has completed its full sync |
| Load | SET, 50 clients, P=1, 1M requests, `redis-benchmark` on CPUs 3–5. Modes alternate, 3 reps each |
| Replica lag | `6l/soak/repl_check.py probe`, running throughout |
| After the load | `repl_check.py converge`, plus a 300-key value comparison of the benchmark keys |

## Reading

- **The append path:** the replicated primary's counters show `coalesce_gained = 0` and every batch holding 1 frame. Each write a replica will see takes the immediate per-command `append`, exactly as #121 described.
- **Worse than coalescing off:** at 54k rps, the replicated primary is slower than standalone with coalescing **off** (64.5k, Test A). Fan-out costs about another 2 µs per write on top of the uncoalesced AOF write.
- **Replica health:** lag and convergence are healthy. The penalty is in the primary's write path, not in replication correctness.

## Decision

The 6N-1 rule called for both conditions; both are met:

| Condition | Required | Measured |
|---|---|---|
| Writes per command, replicated | about 1 | 1.00 |
| Writes per command, standalone | > 5 commands per write | 10 |
| Throughput penalty | ≥ 20% | 55% |

**Recommend Phase 6N-B, design only.** Implementation needs separate approval.

## Not done

- No WebSocket-subscriber variant (`OBSERVER=ws-sync`, already available in the 6N-0 kit). The replicated case alone settles the question.
- No change to replication or fan-out code.
