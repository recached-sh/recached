# v0.6.0 Phase 6N-1: replication-enabled AOF profile (Test B)

**Status: NOT VERIFIED. No measurement taken: the host was not idle (see the Test A report).**

## Why this test exists

#121's own description: "Writes a replica, browser or watcher will see still `append` per command: one `write(2)` each." So with a replication listener configured, the 6M coalescing does not apply.

Evidence so far:
- **Code:** the RC source still has the per-command append on that path.
- **6M macOS counters** (`../6m/mac-indicative/ab-repl/`): about 1.0–1.4 commands per write.
- **Missing:** the Linux throughput and CPU cost of that path.

The 6N-0 kit's phase H only *enables* the listener (`RECACHED_REPL_ENABLE=1`), with no replica attached. It therefore measures neither replica lag nor convergence.

## Design (`run-targeted.sh`, `RUN=B`)

Two modes, alternated, 3 reps each:

| Mode | Primary | Replica |
|---|---|---|
| `standalone` | AOF everysec, 1 worker, **no** replication listener, CPU 0 | — |
| `replicated` | the same, plus `RECACHED_REPL_ENABLE=1`, CPU 0 | `RECACHED_REPLICAOF`, 1 worker, CPU 2. It must hold the 100k preloaded keys before the load starts |

**Load:** SET, 50 clients, P=1, 1M requests, 100k-key space, `redis-benchmark` on CPUs 3–5.

**Recorded per run (`B/results.txt`):**
- rps and p99;
- primary CPU-seconds;
- AOF counter deltas: write calls per command and frames per batch;
- replica lag p50 / p99 / max from `6l/soak/repl_check.py probe`. That is a 20 Hz write-then-read probe, used because Recached's INFO has no replication offsets;
- convergence time and DBSIZE match from `repl_check.py converge`;
- a 300-key value comparison of the benchmark keys;
- any `panicked` or `ERROR` in the server logs.

**Not included:**
- A WebSocket-subscriber variant. The 6N-0 phase H kit already has `OBSERVER=ws-sync:200:key:*`, if wanted later.
- Any change to replication or fan-out.

## Decision rule

**Phase 6N-B** (watermark-gated AOF fan-out, design and independent review only) is justified if both hold:
- the replicated primary shows about 1 write per command, while standalone shows more than 5;
- the replicated primary's throughput penalty is at least 20%.
