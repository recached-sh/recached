# v0.6.0 Phase 6N-C5A: what replication fan-out costs

**Answer: a connected replica costs the primary about 1.35 µs per write (P=1) and 1.33 µs (P=16). About 70–80% of that is kernel time, and almost all of it scales with replica sender *flushes*, not with frames.**

At P=1 the old sender flushed 3.6 frames at a time; at P=16 with the coalesced AOF, 3.8. Each flush is a socket `send` on loopback, which on the primary's CPU also runs the replica socket's TCP receive and wakes the replica. It is also an acknowledgement the primary later reads.

The per-frame suspects the brief listed are each small: the frame copy, backlog, stream lock and channel enqueue.

## How it was measured

`perf` is still not installed, and `kernel.perf_event_paranoid=2`. Nothing was installed and no sysctl was changed. Instead:

| Tool | What it gives | Limits |
|---|---|---|
| [`tools/uprof.c`](tools/uprof.c), about 200 lines of C | Calls `perf_event_open(2)` directly on the server's threads with `exclude_kernel=1`, which paranoid 2 allows for one's own processes. Gives **user-space counters** (cycles, instructions, branch, cache and L1d misses, task clock, context switches) and **user call-stack samples** through the CPU's LBR call stack (Coffee Lake, 32 entries, no frame pointers needed). | Kernel execution is excluded, so the kernel's share is the process's **system time** from `/proc`. LBR holds 32 calls, so outer async frames are lower bounds. |
| [`tools/symbolize.py`](tools/symbolize.py) | Resolves samples against a symbolized build of the same source (frame pointers, line tables; it is not the benchmark binary). `--breakdown` assigns each sample once, to its **innermost context frame** (fan-out, sender, AOF, stripes, …) × a leaf class (allocator, libc, tokio wake/mpsc/io). | libc resolves only to exported symbols, so `memcpy`-family code shows as the nearest export. |
| `/proc/<pid>/stat`, split user/system, per thread | Kernel share by difference | — |
| `ss -ti` on the replication socket | **Data segments out ≈ flushes**, data segments in ≈ acks, bytes | Segments ≈ flushes on loopback with `TCP_NODELAY` |
| [`run-c5.sh`](run-c5.sh), from 6N-C4's `run-m1.sh` | Unchanged workload, affinity and replica setup. Adds several binaries per run, user/system split, uprof, `ss`. | — |

Raw data: [`fedora-i5-9400f-20261120-samples/`](fedora-i5-9400f-20261120-samples/) (xz samples, maps, `profile.md` per cell).

## The pipeline, from the source

```text
connection task (worker W)
  decode → execute_ordered_write
    lock_write: write-order stripes (tokio Mutex per stripe)
    store.execute
    apply_write_effects_identified
      broadcast_for_at → Vec<u8> RESP frame     (allocs: format! per part)
      on_write_logged(&frame)
        DEDUP? wrap into an envelope            (alloc + copy, DEDUP writes only)
        AOF: inline append / coalesced (queue, yield, lead, wait) / deferred gate
        resp.to_vec()                           (alloc + copy; skipped for a DEDUP envelope)
        ReplHub::fan_out(Vec)
          Arc::new                              (alloc)
          stream: std Mutex                     (held only here; nothing awaits under it)
            offset += 1
            backlog.push_back(frame.clone())    (Arc clone) ; trim → drop old Arcs (may free)
            per replica: pending_bytes.fetch_update; QueuedReplFrame (2 Arc clones)
                         tx.try_send             (bounded tokio mpsc; wakes the receiver)
                         sent.store
          gauge!(backlog bytes)                 (no-op recorder in these runs)
    stripes released (after the fan-out)
  reply

replica sender task (handle_replica), woken by try_send → the LIFO slot of W
  rx.recv; write_repl_frame into BufWriter(64 KiB); try_recv ≤ 512; flush
    → send(2): loopback TCP transmit + the replica socket's receive softirq + wake the replica (CPU 2)
  select! also reads the replica's 8-byte cumulative acks (ReadHalf of tokio::io::split)

replica: BufReader → read_repl_frame (alloc per frame) → offset check → apply under stripes
         → ack (write + flush) whenever its read buffer is empty
```

| Step | Allocates | Copies | Locks | Wakes / syscalls |
|---|---|---|---|---|
| frame build | yes, several | — | — | — |
| `to_vec` | 1 | the frame | — | — |
| `fan_out` | `Arc` box, plus 1 mpsc block per 32 frames | — | stream mutex, uncontended at 1 worker | wakes the sender task |
| sender, per flush | — | frame → `BufWriter` | `tokio::io::split` half lock | **1 `send`** |
| sender, per ack | — | — | split half lock | **1 `recv`**, I/O-driver wake |

The AOF and the replica stream use **identical bytes**: the frame, or its DEDUP envelope when DEDUP replication is on. They come from one owned `Vec` that the WebSocket push may also take.

## Attribution of the replica increment

`rc-coalesced` − `rc-coalesced-norep` is the same AOF path with and without a connected replica. That difference is the cost the brief asks about (6N-C4: "about 1.1 µs/op").

| | P=1 | P=16 |
|---|---:|---:|
| CPU µs/op, total | **+1.38** | **+1.33** |
| — user | +0.40 | +0.25 |
| — **system** | **+0.92** | **+1.08** |
| user instructions/op | +1,154 | +1,087 |
| user cycles/op | +2,129 | +1,946 |

**Where the user-space part goes.** The figures are LBR samples, innermost context × user cycles/op, for the coalesced cell minus the norep cell.

| Context | P=1 coalesced | P=1 norep | Δ | P=16 coalesced | P=16 norep | Δ |
|---|---:|---:|---:|---:|---:|---:|
| replica sender task (recv, select, ack read, flush) + `write_repl_frame` | 947 | 0 | **+947** | 740 | 0 | **+740** |
| tokio scheduler (polling and waking the sender) | 1,999 | 1,658 | **+341** | 844 | 622 | **+222** |
| `fan_out` per-replica enqueue (byte reservation, `try_send`, `sent`) | 232 | 0 | **+232** | 242 | 0 | **+242** |
| `fan_out` backlog, offset, lock, `Arc::new` | 360 | 386 | −26 (noise) | 397 | 326 | +71 |
| connection, store, frame build, AOF, stripes, the rest | — | — | +235 (spread) | — | — | +671 (spread) |

The sender's cost is **per wake/flush**. Replication without AOF at P=16 batches 28.7 frames per flush, and there the sender costs 353 cycles/op. In `coalesced` P=16 it costs 740 at 3.8 frames per flush.

**Where the kernel part goes.**
- System time rises by 0.92 µs/op at P=1, with 0.278 sends/op and 0.239 acks/op. That is about **3.3 µs of kernel time per flush** (send + loopback TCP + the replica's ack).
- At P=16, +1.08 µs/op at 0.262 sends/op gives about 4.1 µs per flush.
- Splitting that between the send and the ack receive is **NOT VERIFIED**: it needs kernel samples, which paranoid 2 forbids. The total and the per-flush rate are measured.

## Two findings that change earlier hypotheses

1. **The replica cost is mostly kernel time, and it scales with flushes.** 6N-C4 guessed at per-frame copies and locks. Measured, those are small. The +0.9–1.1 µs/op of system time and the sender's own cost both follow the number of flushes.
2. **6N-C4's P=16 interaction ("+1.75 µs/op with a replica", "hypothesis: the sender wakes once per scheduling round") is confirmed, with the mechanism identified.** Without AOF the sender batches 28.7 frames per flush. With the coalesced AOF it batches 3.8. Every command's AOF yield hands the worker back, and the sender, woken into tokio's LIFO slot by the first `try_send` after each drain, runs and flushes a few frames.
