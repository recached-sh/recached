# v0.6.0 Phase 6N-C5: targeted performance validation

## Verdicts

| Gate | Result |
|---|---|
| **R1: replication fan-out** | **PASS.** Replicated-primary CPU/op is down 0.68 µs at P=1 and 0.82 µs at P=16, about half and about 60% of the measured replica increment. Throughput is up 13% (P=1) and 35% (P=16), p99 is better, convergence is unchanged, RSS is flat. The cost is higher replica lag, ≤ 1 ms at p50 and ≤ 2 ms at p99 in these runs. |
| **R2: multi-worker latency** | **Not met in the oversubscribed layout. Explained, and absent without oversubscription.** With 4 workers on 2 CPUs (the 6N-C4 layout), coalesced p99 is 2.18 ms against 1.98 ms (+10%), at +12.5% throughput. With 2 workers on 2 CPUs, coalesced p99 is **0.551 ms**, 22% better than the baseline's 0.703 ms and better than inline (0.695 ms), at +17% throughput. |
| **M1: replicated ÷ standalone ≥ 0.85** | **P=1: PASS (0.921).** 0.895 against the baseline build's standalone, and 0.868 against 6N-C4's 121k reference. **P=16: FAIL (0.612).** The per-command AOF wait remains. |

**Tradeoff: replica lag.** The sender now holds each flush to the end of a scheduling round:

| Cell | Lag p50 | Lag p99 |
|---|---|---|
| Coalesced | +0.2–0.3 ms | flat |
| Deep-batching cells (`inline`, repl without AOF) | up to +1 ms | up to +2 ms, to 5.8 ms at `inline` P=16, where Redis/Valkey sit at 2.5–2.8 ms |

No client waits on the replica.

**Allocation and retention.** Steady-state RSS is unchanged. Bytes outside the queue's byte budget are bounded by the 64 KiB send buffer per replica ([optimization report](V0.6N-C5-REPLICATION-OPTIMIZATION.md#memory-ownership)).

**Reading.** Whether the coalesced tail regresses against inline depends on whether workers outnumber CPUs, not on the coalescer policy. The [multi-worker report](V0.6N-C5-MULTIWORKER-LATENCY.md) shows this by isolation: F1 and F2 change nothing, and removing fsync changes nothing.
- **Oversubscribed:** this run's final coalesced p99 is 0.19 ms above the baseline's, with non-overlapping ranges.
- **The earlier ablation run:** #141 alone and F1 alone each matched the baseline's p99 (2.04–2.06 against 2.04 ms).
- So in that regime the tail moves by about ±0.2 ms between runs. 6N-C5 did not reduce it.
- **Without oversubscription:** 6N-C5 made coalesced the best cell on both throughput and tail.

## M1 reassessment

| Ratio (medians) | P=1 | P=16 | Threshold |
|---|---:|---:|---:|
| 6N-C4 (`625f88a`), its own run | 0.805 | 0.460 | ≥ 0.85 |
| base, this run (base `coalesced` ÷ base standalone) | 0.791 | 0.428 | |
| **final `coalesced` ÷ final standalone** | **0.921** | **0.612** | |
| final `coalesced` ÷ base standalone | 0.895 | 0.576 | |
| final `coalesced` ÷ 6N-C4 standalone reference (121,197 / 470,146) | 0.868 | 0.612 | |
| final `coalesced` ÷ Redis + replica | 0.737 | 0.598 | |
| final `coalesced` ÷ Valkey + replica | 0.763 | 0.626 | |
| final standalone ÷ Redis (Redis has a replica attached: flatters Recached) | 0.800 | 0.977 | (AOF ≥ 0.90× Redis: release gate) |
| final repl, no AOF ÷ final standalone | 0.946 | 1.024 | |

- **P=1 passes M1 against every reference.** The fan-out was the P=1 limit, as 6N-C4 found, and it has been cut.
- **P=16 fails** and remains the per-command AOF wait. With no AOF, replication alone reaches 1.02× standalone at P=16. The coalesced replicated path reaches 0.61×. The gap is the AOF stage each command waits for in turn before its fan-out. The sender change cannot remove it: the profile shows the sender now flushes 30 frames at a time at P=16, as many as without AOF.

## Not measured

- 4-worker cells with **no** oversubscription and more than 2 workers: this 6-core host lacks the CPUs while keeping the generator off the server's cores.
- Kernel-side split of the remaining replica cost (needs `perf_event_paranoid ≤ 1`).
- A sustained run of the final build. None was planned for this phase, per the brief: the release candidate needs one default-mode soak.
