## Changes

| File | Change | Why |
|---|---|---|
| `server-native/src/propagation.rs`: `resp_push` | Computes the frame's exact length (`resp_push_len`, checked arithmetic, `checked_ilog10` digit counts), allocates once with that capacity, writes the `>n` header with `write_push_header` and each part with `write_bulk` | The old body made 8 allocator calls per SET frame (a `String` per header, `Vec` growth) and went through `core::fmt` per part. This was 1,921 cycles/op, 16% of user cycles at P=1 and 29% at P=16 |
| `propagation.rs`: `broadcast_for_at`, `HSet` arm | A `Vec<&[u8]>` of borrowed slices with exact capacity, instead of a `Vec<Vec<u8>>` of copies plus a second `Vec` of slices | Every field and value was copied once just to build the frame |
| `propagation.rs`: `MSet` arm | The same | The same, for keys and values |
| `propagation.rs`: `Incr`/`Decr`/`IncrBy`/`DecrBy` arm | The new value is formatted by `format_i64` into a 20-byte stack buffer, instead of `n.to_string()` | One allocation per counter write |
| `core-engine/src/resp.rs` | `format_i64` changed from `pub(crate)` to `pub`. New `pub fn write_push_header(out, len)` beside `write_array_header` | Reuse the reply encoder's existing allocation-free formatting rather than add a second one. core-engine is `publish = false`, and no crate re-exports `resp::*` (checked in review) |
| `server-native/src/tests/frame_encoding_6oa.rs` (new) | Byte parity, fixture, hand-written frames, allocation count | [Correctness tests](V0.6O-A-CORRECTNESS-TESTS.md) |
| `server-native/src/tests/fixtures/broadcast-6oa-baseline.bin` (new), `.gitattributes` (`*.bin -text`) | 249,639 bytes, sha256 `bf376cb9…8a54`, generated on `a697f54`. `-text` so no checkout converts its CRLFs | The bytes before the change |
| `server-native/src/tests/request_path.rs` | `measure_with_aof`, `BENCH_AOF=everysec\|no\|always` for `request_path_bench`, `allocations_in`, and the `aof_logged_writes_stay_within_their_allocation_budget` test (SET ≤ 5, INCR ≤ 4, HSET ≤ 7) | Measure, then hold, allocations per command on the standalone AOF path. Before PR 2 these were 11.05, 11.95 and 20.05 |
| `server-native/src/tests.rs` | `mod frame_encoding_6oa;` | |

**Not changed:**
- the AOF queue, batches, the gate, `LeadOnDrop`, fail-stop;
- the stripes and `on_write_logged`;
- DEDUP (`dedup_wrap` is unchanged, and covered by the fixture);
- replication, WebSocket push routing;
- any default or configuration.

There is no `unsafe` and no new dependency.

## Allocations per command

| Workload | no AOF, base → PR 2 | AOF `everysec`, base → PR 2 | ns/cmd with AOF, base → PR 2 |

| INCR | 0.92 → 0.92 | **11.95 → 2.95** | 2,038 → 1,655 (−19%) |
| HSET | 0.00 → 0.00 | **20.05 → 6.05** | 1,758 → 1,284 (−27%) |

**The no-AOF timings.** These in-process runs gave PR 2's build 546 → 591 ns for SET without the AOF, +8%. It is the same code path, untouched by the change, so this is a code-layout or sandbox-noise effect. The native no-AOF control in [the performance report](V0.6O-A-PERFORMANCE.md) is the arbiter.
