## Why SET P=1 cannot reach 0.90× through AOF work alone

| Configuration | Recached / Redis |
|---|---:|
| No persistence, SET P=1 | **0.815×** (A1a), **0.830×** (V3) |
| AOF `everysec` before PR 2 | 0.77–0.81× |
| AOF `everysec` after PR 2 | 0.86× |

Recached's AOF path is now *cheaper relative to its own no-AOF path* than before: 123k/151k = 0.82 of its no-AOF throughput, against Redis's 143k/182k = 0.79. So the remaining SET P=1 distance to 0.90× is no longer an AOF cost. It is the no-persistence command path, Phase 6O-B's scope:
- Recached's no-AOF SET costs 4.4 µs/op against Redis's 3.7.
- Most of that is system time per request: 3.37 against 2.98 µs.

What is left on the AOF path (user cycles/op, after PR 2):

| Component | cycles/op | Note |
|---|---:|---|
| Gate and scheduler | ≈ 3,270 | The batching mechanism |
| Ordered path, `on_write_logged`, stripes | ≈ 1,690 | The ordering contract and the owned `Command` |
| `write(2)` system time | ≈ 0.6 µs/op | |

Reducing them means changing how logged writes are scheduled or executed, not a narrow CPU fix.
