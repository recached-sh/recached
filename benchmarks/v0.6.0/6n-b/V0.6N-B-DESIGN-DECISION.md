# v0.6.0 Phase 6N-B: design decision

## Recommendation: CONDITIONALLY APPROVED

**Status of this recommendation.** It is the engineering recommendation only. **Implementation is not authorized** until the maintainer decides. Nothing in 6N-B changed production code, configuration defaults or protocols. `main` was not touched, and v0.6.0 was not tagged or released.

### Why not APPROVED FOR IMPLEMENTATION

**1. The ordering argument is sound, but it is not yet backed by code or tests.**
- The model ([`model/`](model/)) checks the core interleavings.
- The review found two High-severity gaps in the first draft (a reply path and a cross-scope keychange). It then found a third High in the author's own fix (silent keychange loss on token renewal), and further issues in two rounds of mitigations.
- The deterministic hooks and mutation tests in the [validation plan](V0.6N-B-VALIDATION-PLAN.md) are what would turn this into evidence.

**2. The benefit of A over D is estimated, not measured.**

| Design | Estimated µs/op | vs today (14.0) |
|---|---|---|
| A | 7–8 | — |
| D | 8–9 | — |

These come from run differences, not profiles; the 6N-1 host had no `perf`. D might close enough of the gap on its own.

### Why not REJECTED

- The current architecture can satisfy every required guarantee (G1–G10, A–H) with the additions N1–N13.
- The additions are contained in four places:
  - the performer's release step;
  - the reply-ticket rule;
  - the drained/cut barriers;
  - the dequeue checks.
- No new task type, lock order, protocol message or file format is needed.
- The `inline` path stays available unchanged as the default and the rollback.

## Remaining bounded risks

| Risk | Bound |
|---|---|
| Implementation diverges from the design | Feature switch; default `inline`; mode-parity CI; deterministic tests |
| Drain stalls on replica attach, promotion or SAVE | One batch (`write(2)`, or `fdatasync` under `always`) with all stripes held, as rare as those events. QSUB waits outside the stripes |
| Pending memory | `AOF_PENDING_BYTES` cap plus one frame per in-flight writer; past the cap, today's inline behaviour |
| A delta-applying client double-counting a routed push it also read (RV-15) | Pre-existing; documented; only `qstate` is a consistent base |
| Four-worker coalescing (2.2 cmds/write) | Not addressed by A or D; a separate investigation |
