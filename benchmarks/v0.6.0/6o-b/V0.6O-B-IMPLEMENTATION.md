## PR 2: the shared TCP request path

### (a) Cross-connection reply coalescing (`reply_coalesce.rs`)

At the end of a read batch, `handle_tcp` used to flush its `BufWriter` at once. It now runs:

```rust
if !writer.buffer().is_empty() && aof_pending.is_empty() {
    reply_coalesce::before_flush().await;   // yield_now once, unless backed off
}
writer.flush().await
```

and records each read batch it is about to execute with `reply_coalesce::note_batch()`. `aof_pending` is the connection's AOF ticket queue (the same `Arc<DeferredAof>` the gate drains).
- **With tickets queued**, the gate's own coalescing yield (6M) applies instead, so a flush yields at most once and the AOF path behaves exactly as before.
- **With none** (no AOF, or a read-only batch), this yield applies.

The back-off state is a `thread_local!` of three `Cell`s per worker: the batch counter, `skip` and `misses`. `begin()` decides whether a flush yields: not while `skip > 0`. `end()` scores the yield:
- **Gain:** the worker's batch counter moved while the task was deferred, or the task was resumed on another worker.
- **Miss:** anything else. Two misses in a row set `skip = 32`.

The constants are `MISSES = 2` and `BACKOFF = 32`, the AOF coalescer's values.

`RECACHED_REPLY_COALESCE` is parsed in `main.rs` like `RECACHED_AOF_COALESCE`:
- `on` (the default), `off`, `1`/`0` and `true`/`false` are accepted.
- Anything else is a startup error.
- `off` is logged at startup.

### (b) The overflow arm (`connection.rs`)

`overflow_rx.recv()` was an arm of every pass of the connection's `select!`, and was polled whenever the read arm was pending. That is once or twice per command at P=1: a receive poll, coop-budget accounting and an `AtomicWaker` registration. The only senders are the pubsub sender `ps_tx` and the WATCH subscriber `watch_subscriber`. Neither leaves the connection until a SUBSCRIBE, PSUBSCRIBE or WATCH registers it.

The arm is now `if overflow_armed`.
- `overflow_armed = true` is set at those three handouts, just before the sender is registered.
- It is sticky, so a connection that ever subscribed or watched polls the arm for good, exactly as before. The WebSocket handler is unchanged.
- The first commit derived the flag from the subscription state at the top of each loop pass. The independent review showed this missed an overflow signalled while a SUBSCRIBE/UNSUBSCRIBE or WATCH/UNWATCH pair ran inside one read batch ([review](V0.6O-B-INDEPENDENT-REVIEW.md), finding 1). Arming at the handout is exact: no sender can exist before it.

### (c) The AOF gate's empty check (`persistence.rs`)

`DeferredAof` gains `queued: AtomicUsize`. It is stored with `Release` under the mutex after every push and pop, and loaded with `Acquire` by `is_empty()`. `pop()` returns `None` without the lock when it reads 0.

Every push and pop runs on the connection's own task:
- `AOF_DEFERRED` is task-local;
- the gate belongs to the task.

So the unlocked read cannot miss a push in practice. If it ever raced one, reading 0 is the same outcome as a pop taking the lock just before that push, which the mutex allowed too. With tickets queued, `pop` behaves exactly as before.

### Rollback

- `RECACHED_REPLY_COALESCE=off` disables (a) at runtime, with no rebuild.
- (b) and (c) have no switch. They are not observable except as CPU, and reverting the PR's commit removes them.

## PR 3: LPUSH, RPUSH, SADD

### (a) Decoder builders (`core-engine/src/request.rs`)

`build()` gains three exact shapes next to MSET and DEL:

| Shape | Accepted when | Builds |
|---|---|---|
| `LPUSH key v…` / `RPUSH key v…` | n ≥ 3, key passes `Args::key` (UTF-8 + `validate_key`) | `Command::LPush`/`RPush(key, values)` with the values' bytes as they arrived |
| `SADD key m…` | n ≥ 3, key passes `Args::key`, every member is UTF-8 | `Command::SAdd(key, members)` |

Any other frame of those commands goes to `Args::general`, so the general path produces every error and every reply for it: wrong arity, a non-UTF-8 or invalid key, a non-UTF-8 member, or any frame `scan` did not accept. The names match ASCII case-insensitively, as for every other builder. A spelling only Unicode upper-casing maps to these names, such as `ſadd` (U+017F upper-cases to `S`), is not matched and reaches the general path, which treats it exactly as before; the differential corpus includes `ſadd` and `lpuſh`.

### (b) Probe accounting, by reference (`core-engine/src/store.rs`)

- The three `execute_inner` arms become `push()` and `sadd()`. Each takes its key's one write slot through `typed_entry!` with the probe.
- `execute_inner_probed` and `execute_inner_ref` gain arms for them, and `probe_eligible` lists them.

The server runs every unlogged write by reference. Such a write:
- is accounted from its own slot: no sort, no `entry_state` before and no lookup after;
- copies each list value once into the list;
- copies a set member only when it is new, through `SetMember for &str`, so a re-added member allocates nothing. Owned members (AOF replay, replica apply) still move in.

On a capped store, `probe_eligible` also admits these writes to the 6L reservation fast path, as it already admits SET and HSET. The new tests below check that the reservation path and the gated path agree on these writes.

### Rollback

Revert the PR. It has no switch: its effects are CPU and allocation counts, and replies and accounting are identical by construction and by test.

## Rejected approaches

Full list with reasons: [the design](V0.6O-B-OPTIMIZATION-DESIGN.md).

| Approach | Why not |
|---|---|
| Yield before *every* flush, with no back-off (the prototype) | It cost one client 2.9% |
| A process-wide back-off state, as the AOF coalescer has | It needs a `fetch_update` per flush on a shared cache line in multi-worker mode. The per-thread state needs none |
| Yield even with AOF tickets queued | That double-yields with the gate. The gate's coalescer already decides for logged writes, so the AOF path stays exactly as it was |
| `read`/`write` instead of `recv`/`send` | They are not cheaper (`tcpcost`) |
| A timer, or a batch size, for replies | Forbidden, and unnecessary |
| A borrowed `CommandRef` for LPUSH and SADD, so even the decoder's copy goes | A larger change to the borrowed-execution framework (`execute_ref_into`) for an estimated ≈ 300–600 cycles more. Recorded as a follow-up |
| An MSET multi-key probe (one lookup per key) | Medium–high risk in the capacity and reservation accounting for multi-key writes. Recorded with its measured cost |
| A direct ZADD builder | The option grammar and float parsing make its equivalence surface large, for a control command at 0.91× |
