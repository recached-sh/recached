# v0.6.0 Phase 6O-B: ranked optimization candidates

**Answer.** Six candidates were costed from the [CPU profile](V0.6O-B-CPU-PROFILE.md). Three of them are shared by every command and were prototyped on the native host before any production change.

The largest is not in Recached's code at all. It is **when replies reach the kernel.** Redis writes every client's replies after it has read all of them. Recached replied the moment each command ran, which made the benchmark's client threads sleep and wake once per reply. Each wake-up is kernel work inside the server's `send(2)`, on the server's CPU.

Rejected or not pursued:

| Idea | Why not |
|---|---|
| Different syscalls (`write`/`read` like Redis) | The `tcpcost` microbenchmark puts `send` 60 ns *cheaper* than `write` and `recv` 120 ns cheaper than `read`. Syscall counts are identical: 1.0 `recv` and 1.0 `send` per command, the same as Redis's `read`/`write`, and no EAGAIN reads (Tokio clears readiness on short reads) |
| Batching replies on a timer | Forbidden by the brief and unnecessary: #1 batches only work that is already runnable |
| Removing the per-command duration histogram (`Instant::now`) and metrics (≈ 230 + 300 cycles) | It changes observable metrics. Out of scope |
| A different hash (DashMap uses SipHash-1-3) | A keyspace-wide change, out of scope ("broad memory-layout optimizations"), and only 120–230 cycles per single-key command |
| Changing `TCP_READ_BUFFER_BYTES` or the 32 KiB `BufWriter` | Nothing in the profile points at them. The copy from the stack buffer into `buf` is under 1% |
| Bypassing the `AofGatedWriter` without an AOF | #3 removes its measurable cost. A separate writer type per persistence mode would duplicate the reply path for ≤ 100 more cycles |

## Candidate 1 in detail

**Mechanism.** A connection that has replies buffered, and no AOF batch to wait for, calls `reply_coalesce::before_flush()` before `writer.flush()`:

- A `tokio::task::yield_now()` defers the task until the worker has run every other runnable task and polled the I/O driver once.
- The other ready connections therefore read, execute and buffer their replies first.
- The replies then leave back to back, as Redis's `beforeSleep` writes them.

The AOF gate has done exactly this since 6M, for connections with AOF frames queued. Its yield is the AOF's group commit. A flush with a batch to wait for is left to the gate, so it yields at most once per flush.

**Back-off.** A yield gains if another connection on the same worker recorded a read batch while it was deferred (`note_batch`, a thread-local counter). Two misses in a row skip the next 32 flushes; then the next one probes again. These are the AOF coalescer's constants. The state is per worker thread:

- There is no shared atomic on the hot path. A process-wide `fetch_update` per flush would bounce a cache line between workers in multi-worker mode.
- A worker's own recent experience predicts its next yield.

A task resumed on another worker (stolen) records nothing.

**Bounds.**
- A reply waits for at most the tasks already runnable on its worker, plus one zero-timeout driver poll.
- No timer is involved, and nothing waits for input that has not arrived.
- Buffering is unchanged: the same 32 KiB `BufWriter` and the same per-read-batch flush.

**What it does not change.**
- The content of replies, their order on a connection, or what a reply waits for. The AOF gate still holds every reply behind its commands' batch.
- Command execution order: commands are executed before the yield, exactly as before.

**Kill switch.** `RECACHED_REPLY_COALESCE=off` gives immediate flushes, the behaviour before 6O-B. It is parsed like `RECACHED_AOF_COALESCE`, and an invalid value is a startup error.

## Candidates 4 and 5 in detail

**4. Decoder builders.** `RequestDecoder::decode_any` already builds `MSET` and `DEL` directly. LPUSH, RPUSH and SADD join them as exact shapes:
- **LPUSH and RPUSH:** n ≥ 3, the key passes `key` (UTF-8 and `validate_key`), and the values are payloads.
- **SADD:** n ≥ 3, the key passes `key`, and every member is UTF-8 (members are identifiers: `is_payload_index` is false).

A frame that fails any check goes to the general path, which produces the error. The equivalence test now runs those names, in all cases plus near-misses (`LPUSHX`, `LPUS`, `SADDX`), through its argument × position × arity matrix, including non-UTF-8, empty, oversized and CRLF arguments, and through DEDUP envelopes. ZADD was left out: its option parsing and float grammar make an exact-shape builder a larger equivalence surface for a control command already at 0.86×.

**5. Probe accounting.** LPUSH, RPUSH and SADD take exactly one write slot, through `typed_entry!`, as HSET does. Passing the probe to that slot lets `run_write` account from the write's own lookup. The generic multi-key path instead sorts the scope, takes `entry_state` before, executes and reads the state again after: three hash lookups instead of one. The by-reference arms copy each value once into the list, and each new set member once, instead of cloning the whole command to move it. A re-added SADD member, the common case in the benchmark's saturated set, now allocates nothing.

For capped stores, `probe_eligible` also admits these writes to the 6L reservation fast path, as it already does for SET and HSET. They have a `growth_bound`. The reservation path is generic, and its tests apply as they are.
