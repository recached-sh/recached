# v0.6.0 Phase 6N-C4: independent review of the coalescer correction

**Reviewed:** commit `41403f2` against `dev` `ef2c8c9`. The review fed into PR #136.

**Reviewer:** an engineer-agent that did not write the change. It did a static review only, because a benchmark was running on the host. It was asked to construct counterexamples, not to approve the design.

**Verdict:** **APPROVE WITH NITS.** It found no correctness, durability, ordering, liveness or security defect. It asked for one test gap (F5) to be closed before merge, and that was done in `3ce871a`.

## Findings

| ID | Severity | Finding | Resolution |
|---|---|---|---|
| F1 | Low | Another worker's inline leader, or an `always` drain on the blocking pool, can hold `busy`. A yield then gets credit for frames that would have joined anyway, because the busy performer sweeps them. Under a saturated `always` the fan-out coalescer therefore never backs off, even though its yields buy nothing. The cost is one scheduler pass per append, next to an `fdatasync` that is already running. | **Accepted and bounded.** It does not occur in the 1-worker `everysec` M1 cells (`lead_busy` = 0 in every run). Follow-up: have `queue_only` report `busy`, and neither yield nor observe when it is set. |
| F2 | Low | Misses are counted across all writers in a row, and the last writer into each batch always records one. With about 2 writers per batch (e.g. multi-worker), gain/miss alternate, and any one-frame batch in between triggers a back-off, so the back-off is sensitive. | **Accepted.** The M1 4-worker cell measures it. Follow-up: observe once per batch (e.g. whoever leads or finds the batch written, with gain meaning more than one frame), so that "misses in a row" means "one-frame batches in a row". |
| F3 | Low | `recached_aof_coalesce_gained/_missed` changed meaning. They are now gate-only, whereas 6N-C's `rc-coalesced` rows counted fan-out yields there. | **Documented** in the [implementation note](V0.6N-C4-IMPLEMENTATION.md) and the PR. The fields are unreleased (absent in v0.5.x). |
| F4 | Low | The connection gate still leads after its yield unconditionally, and still uses the old signal. On a node with both deferred and coalesced writers (AOF without replication, plus watchers or WS routes), it can still write a batch that a coalesced writer just opened. | **Accepted.** The brief kept the validated gate path unchanged. Follow-up candidate, listed in the [release gate](V0.6N-C4-RELEASE-GATE.md). |
| F5 | Medium (test gap) | Every new test ran on one thread. Nothing exercised the skipped lead with 2+ workers, the `busy` hand-off, migration, `always` concurrency, flush sealing, or the INFO fields. | **Fixed** (`3ce871a`): `pipelined_writers_on_four_workers_strand_nothing` (4 workers × `no`/`everysec`/`always`), `a_batch_sealed_by_a_flush_is_a_miss`, and an INFO field assertion. A deterministic mixed gate-plus-fan-out batch test was not added: the gate path is unchanged, and the whole suite also runs in `coalesced` mode. |
| F6 | Low | Stale docs: the `AofTail` comment, the `aof_stats` module comment, and the 6N-C Option D note ("every writer leads after its yield") | **Fixed** in code comments (`3ce871a`). The 6N-C report is left as the record of that phase; [the implementation note](V0.6N-C4-IMPLEMENTATION.md) supersedes its pseudocode. |
| F7 | Nit | Test C's and Test F's batching bounds depend on how tokio's `yield_now` defers wake-ups. The bounds are lenient. | Noted. Tests A, B, D and E poll by hand and do not depend on it. |
| F8 | Nit | Cost on the default `inline` path: one relaxed store per frame, under a lock already held, and 8 bytes per batch | No action. `inline` M1 numbers are in [M1](V0.6N-C4-M1-PERFORMANCE.md). |
| F9 | Nit | `found_written` also counts batches that failed | **Fixed** (doc): it means "found its batch completed". |

## Questions the reviewer answered

| Area | Finding |
|---|---|
| Accuracy of the gain signal | No yield is counted as a gain unless a frame joined the writer's own batch. A batch sealed by `flush`, a fresh batch, a truncate, or a batch already taken can only produce a miss. The one inaccuracy is the credit in F1. |
| Memory ordering of `AofDone::frames` | No correctness property depends on it. It is stored under the queue lock and is final once the batch is taken. A stale read after migration can only produce a false miss. `is_complete()` is `OnceLock::get` (Acquire). |
| Liveness after the skipped lead | No counterexample. Every producer leads unless its own batch has completed. `lead()` returns early only on an empty queue or `busy`, and both performers re-check under the lock before releasing the writer role. A pre-existing, unchanged caveat: a `LeadOnDrop` during runtime shutdown under `always` may hand work to a dying blocking pool. That frame was never acknowledged. |
| Races between queue, seal, lead and complete | `complete()` follows `perform` + `settle`, including `fdatasync` under `always`. `is_complete()` can never be true before the frame is written, or synced under `always`. |
| Locks across `.await` | No new awaits. The std queue mutex is never held across one. Stripes are held across the yield exactly as before. |
| Back-off | A single client backs off as intended. Serialized writers yield on about 6% of appends. P=16 gains for real. See F1 and F2 for the edges. |
| Replication ordering and fail-stop | Unchanged |
| Default-path cost | Negligible (F8) |
| Tests | A, B, D and E are deterministic and test what they claim. C fails on the old code. The gains-≤-shared-frames invariant holds by construction. |
