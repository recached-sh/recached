# v0.6.0 Phase 6N-C4B: where the replicated primary's CPU goes

## Unavailable profiling data

| Measurement | Status |
|---|---|
| `perf stat`: instructions/op, cycles/op | **NOT VERIFIED.** `perf` is absent on the Fedora host and `kernel.perf_event_paranoid=2`. Installing it or changing host configuration needs the maintainer's authorization, which was not given. |
| `perf record` call stacks | **NOT VERIFIED**, for the same reason |
| Allocation and reference-count overhead, replication stream mutex hold time, per-function attribution | **NOT VERIFIED.** No counter exists, and there was no sampling profiler. |
| Socket `send`/`recv` syscall counts | **Not measurable** with `/proc/<pid>/io`: `syscr`/`syscw` count `read`/`write`-family calls, and tokio's TCP I/O uses `send`/`recv`. The `syscalls/op` column therefore counts the AOF file's `write(2)` calls, and it matches the AOF counters (1.00/op inline). |

**What was used instead:**
- process CPU time from `/proc/<pid>/stat`;
- per-thread CPU by thread name;
- context switches summed over threads;
- Recached's AOF counters, including `write(2)` time;
- an **ablation**: the same binary in configurations that each add one cost.

Every figure below is a difference between measured configurations. The internal breakdown of a component is a hypothesis unless it is marked as measured.

## Attribution by difference (CPU µs/op)

| Increment | P=1 | P=16 | What it contains (observed / *hypothesis*) |
|---|---:|---:|---|
| Ordered write path plus deferred AOF: `standalone − noaof` | +1.86 | +0.93 | *Stripe locks, building the broadcast frame, the per-flush gate yield, the AOF `write(2)` (measured: 0.32–0.74 µs/op)* |
| Per-command AOF wait on the replicated path instead of the gate's per-flush wait: `coalesced-norep − standalone` | **+0.15** | **+0.71** | The coalesced path yields once per command (measured: 1.00 yields/cmd, against the gate's 0.062 at P=16). At P=1 that is one command per flush anyway, so the paths cost the same. At P=16 the gate yields once per pipeline of 16. |
| A connected replica on the AOF path: `coalesced − coalesced-norep` | **+1.12** | **+1.29 to +1.36** | *Per frame: copying the frame (`resp.to_vec()`), an `Arc`, the stream mutex, backlog push and trim, a channel `try_send`, waking the sender task, buffered framing; per burst: a socket flush; reading the replica's acks* |
| A connected replica without AOF: `repl-noaof − noaof` | +3.00 | +1.18 | The ordered path, which `noaof` skips, plus the replica fan-out above |
| AOF on top of a connected replica: `coalesced − repl-noaof` | **+0.13** | **+1.75** | At P=1 the coalesced AOF is nearly free. At P=16 it is the per-command wait (+0.71 without a replica), and that wait costs more with a replica attached. *Hypothesis: the sender task wakes once per scheduling round instead of once per pipeline.* |

## Facts and hypotheses

**Observed:**
- With a replica attached, the replicated primary's AOF costs about 0.13 µs/op at P=1. The P=1 gap to standalone is the replica, not the AOF.
- Replication with no AOF at all reaches only 0.815–0.84× standalone at P=1.
- At P=16 the replicated AOF path costs 1.75 µs/op beyond replication alone, and throughput is 216k against 465k.
- With coalescing, AOF `write(2)` cost is at parity with standalone.

**Hypotheses (not verified without `perf`):**
- Inside the +1.1–1.4 µs/op replica cost, which of frame copy, mutex, backlog, channel or sender wake-ups dominates.
- That the P=16 interaction between the per-command wait and the replica comes from per-round sender wake-ups.

To verify both, authorize installing `perf` on the host (`dnf install perf`, and `kernel.perf_event_paranoid ≤ 1` for kernel samples), then run `perf record -g` on the primary in the `rc-coalesced` P=1 and P=16 cells.
