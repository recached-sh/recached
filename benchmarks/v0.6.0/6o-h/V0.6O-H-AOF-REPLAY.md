## 1. What a file holds

| Mode | Meaning | Written as |
|---|---|---|
| `Empty` | no record yet: new, or emptied by a checkpoint | — |
| `Timeless` | begins with `FORMAT`, and every record since was written with expirations logged | RESP2 arrays (`*N`) |
| `Legacy` | anything else | RESP3 pushes (`>N`), as every release writes |

The writer tracks the mode under its queue lock, so it describes the file as the queue will leave it:

| Transition | Where |
|---|---|
| set from the replay at startup | `start_expiry_log` |
| `Empty` → `Timeless` | `begin_expiry_log` (startup) or `truncate_then(true)` (checkpoint), which queue `FORMAT` under the same lock hold |
| `Empty` → `Legacy` | the first other record queued into an empty file |
| `Timeless` → `Legacy` | `leave_expiry_log`: no record is needed, since the pushes that follow end the timeless part on replay |
| any → `Empty` | a truncation, at the moment it is queued |

**Default.** Before replay sets the mode, it is `Legacy`. So nothing can write `FORMAT` into the middle of a file.

**A failed truncation.** The mode becomes `Empty` when the truncation is queued, but the file is not emptied. The save fails before anything else is queued: persistence is latched unhealthy, and writes answer `MISCONF` until a `SAVE` succeeds. Records the rejected writes never produce cannot mislabel the file. The next startup reads the mode from the file again.

## 2. Replay (`replay_aof_format`)

Pass 1 (it already read the whole file for the checkpoint and the DEDUP marks) also finds where the timeless part ends:

| Record | Effect |
|---|---|
| The first record is `FORMAT` with `expirylog`, and no unknown must-understand bit | the file is timeless from its head |
| `FORMAT` anywhere else, or a control record of an ignorable kind (`0x80`–`0xFF`) | ignored |
| A control record of another unknown kind, or of an unknown layout | ends the timeless part (logged) |
| A checkpoint marker | as before (the snapshot's own marker moves the replay start) |
| A push (`>N`) | ends the timeless part: an older server appended it (logged) |
| An array (`*N`) | nothing |

Records are classified by value, whatever their encoding: an old binary's checkpoint marker is a push.

**Pass 2.** A record is applied inside `without_expiry` iff the file is timeless at its offset. During the timeless part the store is a follower:
- the file holds the primary's eviction `DEL`s, so the replay chooses no victims of its own;
- it refuses nothing for capacity.

The follower flag is restored at the end and on every error return. The helper reads run in the same mode as the record they belong to: the claimable-member check, and the abandoned-ephemeral discard at the end.

**The snapshot** is loaded keeping every entry (`without_expiry` around `restore`). The replay then drops the expired ones, silently, as a load always did, unless:
- the records it precedes replay timelessly; or
- the AOF is empty on a primary, which begins the format next.

With no AOF configured, `main` drops them right after the load.

## 6. Compatibility

- **Older binaries** read files in the format (`V0.6O-H-PROTOCOL-DESIGN.md` §2.4, 60/60 on v0.4.0, v0.5.1, v0.5.2, `410235b`, `f9a364d`). They replay them by their own rules, as before.
- **Older AOF files** replay on this build exactly as before: the 6O-F legacy-deadline clamp still applies, and the compat matrix's 0.4 and 0.5 upgrade checks run in CI.
- **Downgrade.** The documented procedure is unchanged: `SAVE`, stop, start the older binary.
- **Re-upgrade after a downgrade** needs no step. CI's compat matrix checks it: the older server expires a key silently, recreates it with `APPEND`, and is SIGKILLed. The new server then serves its value (`"new"`, permanent), not the merge onto the stale entry.
- **Limitations** (design §10):
  - a legacy file stays legacy until its first checkpoint after the upgrade;
  - writes accepted after the shutdown save are kept (pre-existing, harmless);
  - an older binary does not gain the new replay guarantees.
