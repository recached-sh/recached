## AOF carryover: standalone `everysec` (3 repetitions)

Redis here is standalone with `appendonly yes`, `appendfsync everysec`.

| Workload | base ops/s | final ops/s | Redis ops/s | **final / Redis** | base / Redis | Paired final / base | 6O-B reported |
|---|---:|---:|---:|---:|---:|---|---:|
| SET P=1 | 132,192 | 131,139 | 158,372 | **0.828** (0.828–0.842) | 0.835 | 1.000 (0.984–1.009) | 0.857 |
| INCR P=1 | 132,218 | 133,324 | 175,778 | **0.771** (0.746–0.783) | 0.758 | 1.017 | 0.767 |
| HSET P=1 | 126,968 | 130,073 | 155,292 | **0.843** (0.838–0.854) | 0.829 | 1.024 | 0.859 |
| SET P=16 | 574,927 | 558,956 | 475,579 | **1.19** (1.17–1.25) | 1.21 | 1.007 | 1.14 |

**No regression on the logged-write path.** The paired changes are 0 to +2.4%, from the borrowed path's earlier decline of logged writes and from C3. The no-persistence gains do not carry over, as the brief warned: a logged write never takes the borrowed path, and its flush is gated by the AOF coalescer, not the reply yield.

The absolute ratios against Redis moved by up to −0.03 from 6O-B's run, at an equal or better paired change. That is Redis's own run-to-run variation on this host (its SET P=1 `everysec` throughput). **The AOF ≥ 0.90× target at P=1 remains unmet.**

## Uncertainty

| Item | Value |
|---|---|
| Throughput spread within a cell set (max−min over median) | 1–4% at P=1 (`spread` column); up to 8% for AOF P=16 |
| redis-benchmark latency quantization | 8 µs below 1 ms (p99 values are multiples); throughput resolution ≈ 0.1% at 30 s cells |
| Paired ratio range, primary gate | ±1.5% around the median for SET and MSET (no change), 1.6–6.4% for LPUSH and SADD (a change) |
| Gate decisions near 0.90 | LPUSH's lowest repetition is 0.914; SET's 0.902. SADD's median is 0.894 with one repetition above 0.90. These follow the brief: no rounding, no single favourable repetition |
| Host | Background: GNOME's indexer at nice 19, stale swap. Mitigated by quiet-start checks and interleaved, paired repetitions, not eliminated |
