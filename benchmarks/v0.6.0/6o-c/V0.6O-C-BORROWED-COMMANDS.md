## What changed

6O-B (#154) decoded these commands straight from the read buffer, but still built an owned `Command` for every one: the key `String`, a `Vec` per value and the vector. The store then copied each value again into the list or set. Now:

| Layer | Change |
|---|---|
| Decoder (`request.rs`) | `CommandRef::{LPush, RPush, SAdd}` are borrowed shapes in `build_ref`, with exactly 6O-B's checks (§ below). Values and members are collected into vectors sized up front. `to_command` gives exactly the command 6O-B's `build()` arms built; those arms are removed, since `build()` calls `build_ref` first |
| Store (`store.rs`) | `execute_ref_into` runs them through `run_probed_write`, the same single-key slot, stripe and probe accounting as the owned path, with `push(&[u8])` and `sadd(&str)`. A list value is copied once, into the list. A set member is copied only when it is new (`SetMember for &str`). On a capped store a borrowed write returns `None` and the owned reservation path runs it |
| Server (`propagation.rs`) | `try_execute_borrowed` turns a write away **before** reading the clock and entering the unordered gate whenever the owned path will run it anyway: AOF on, a replica, push receivers, watchers, ephemeral keys, a capped store or unhealthy persistence. The check after entering the gate is unchanged and stays authoritative |
| Labels (`clients.rs`) | `lpush`, `rpush`, `sadd`, as `command_name` gives for the owned commands |

The decline before the gate came from the review (Medium). Before it, every declined borrowed write entered the gate twice, once only to leave it. That has been true since 6O-B for SET, INCR and HSET, and this PR would have extended it to the collection writes. It matters on the AOF path.

**Kept on the owned path:** AOF logging and replay, replica apply, capped stores, MULTI queueing, DEDUP envelopes, subscribe mode, unauthenticated connections, WebSocket (which decodes with `decode()`, i.e. owned), and every context where a write log, a watcher or a push receiver observes write order.

**Lifetimes:** a `CommandRef` lives inside the `decode_any` match, before the read buffer is compacted, and the borrow checker enforces that. Every stored value owns its data.

There is no new set or list data structure; that is Phase 6P.

### Decode equivalence

The builders accept exactly what 6O-B's did:

| Check | Rule |
|---|---|
| Arity | n ≥ 3 |
| Key | `key_ref`: UTF-8 and `validate_key` |
| List values | Any bytes (`is_payload_index` at i ≥ 2) |
| Set members | UTF-8, as `from_value`'s identifier check |
| Names | ASCII case-insensitive. Unicode-only spellings (`ſadd`, `lpuſh`) go to the general path, which upper-cases them itself |
| Oversized arguments, > 4,096 arguments, frames over the total limit, non-bulk or incomplete frames | `scan` declines; the general path answers |
| DEDUP | The inner command goes `build` → `build_ref` → `to_command`, so it is the 6O-B command; nesting is still refused |

## SADD: what remains, and why it belongs to 6P

SADD gained +3.7% and now sits at about 0.90× (0.882–0.906 per repetition). Its remaining gap to Redis is ≈ 1,840 user cycles per op (5,042 against 3,200). The 6O-B profile put most of it in the set's layout:
- `IndexSet<String>` costs two to three dependent memory accesses per member probe (857 cycles/op at 100,000 members);
- `SetMember for &str` looks a new member up twice (`contains`, then `insert`).

Both are data-structure changes: Phase 6P (memory efficiency), by the brief. The final validation re-measures SADD with 5 repetitions ([performance](V0.6O-C-PERFORMANCE.md)).
