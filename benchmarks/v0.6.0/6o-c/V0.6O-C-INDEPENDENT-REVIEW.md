# v0.6.0 Phase 6O-C: independent review

How the reviews were run:
- Each change was reviewed by an independent agent that did not write it.
- Each reviewer got the diff, the surrounding code and the brief's invariants, not the author's conclusions, and was asked to construct counterexamples and adverse interleavings.
- Reviews were read-only while a native benchmark was on the host. The C3 reviewer ran targeted tests once the host was free.
- Follow-up commits went back to the same reviewer.

## WATCH overflow fix (#157)

**Round 1** (`cff4275`, `615cc16`). The reviewer confirmed the check sits in the right place:
- Every path that notifies a watched key does so while holding that key's stripe, or all stripes. That covers ordered and locked writes, capped stores, the expiry sweep, eviction, FLUSHDB, DEL/RENAME/MSET, other connections' EXECs, replica apply and full resync.
- EXEC takes those stripes before `try_recv`.
- tokio 1.54.1's `try_recv` waits out a send in progress.
- The reviewer could not construct an interleaving in which a watched key changes, overflows, and EXEC still commits.

| # | Severity | Finding | Resolution |
|---|---|---|---|
| 1 | Medium, pre-existing | TCP watchers never use the payload, yet each notification is charged the whole value against the 8 MiB budget. WATCH correctness depends on that budget and on a channel shared with pub/sub. A watch on a 9 MiB hash disconnects where Redis returns a nil EXEC | **Recorded** as a follow-up (a per-connection dirty flag); not in this fix's scope |
| 2 | Low | The `break 'outer` mid-batch discarded the replies of earlier commands that did run | **Fixed**: guards dropped, the batch flushed, then disconnect; test `the_replies_before_a_condemned_exec_in_its_batch_still_arrive` |
| 3 | Low | The concurrent check-and-set test had no `committed > 0` assertion, and 3 s timeouts | **Fixed** |
| 4 | Low | No deterministic test of the in-flight-writer case | **Fixed**: `an_overflowing_write_in_flight_while_exec_waits_never_commits` (fails 3/3 on `be3c90e`) |
| 5 | Low | The WATCH/UNWATCH test asserts a policy, not WATCH safety | **Fixed** (annotated) |
| 6 | Nit, pre-existing | WS WATCH registers without closing the unordered gate; safe only because every WS connection that can WATCH is a counted push receiver | Recorded |
| 7 | Nit | The 2,000-round WS test is costly | Kept: it is the only WS discriminator; ~10 s |
| – | Out of scope, pre-existing | A lazily expired watched key does not dirty EXEC (Redis 6.0.9+ aborts); `execute_locked_write_within_capacity` relies on a `debug_assert` | Recorded |

**Round 2** (`320e46d`). Finding: **the commit message described a flush change that the commit did not contain** (Medium, process). The author had restored `connection.rs` from `HEAD` after a discrimination run with the edit still uncommitted. **Fixed**: the change was re-applied with its test, and the commit amended (`ea83cf8`) so the message is true. The reviewer confirmed the planned order (release the guards, then flush, then disconnect) cannot deadlock, and that the deterministic test is sound.

## C1 reply coalescing (#158)

**Round 1** (`a63c024`):

| # | Severity | Finding | Resolution |
|---|---|---|---|
| 1 | Medium | Scoring a migrated resume as a miss backs the busy case off. In Tokio 1.54 a yielded task migrates almost only when several were deferred and an idle worker stole some, and those had gained | **Fixed**: migration neutral again. Native counters confirmed 30% of yields migrate in the busy case, and none for a lone connection |
| 2 | Medium | The premise of (B) is false for Tokio 1.54: a lone task resumes from its own worker's LIFO slot | **Confirmed** (0 migrations); the one-client cost addressed by the doubling back-off |
| 3 | Medium | A pipeline split across reads still yields on the read that completes one frame | **Fixed**: `partial_left` and `pipeline_tail` |
| 4 | Low | P=2–4 unmeasured | Measured: P=4 at 1 worker, −6.7% throughput, −7% p99 |
| 5 | Low | With AOF tickets queued, P=16 still yields through the gate's coalescer | Documented: by design, the gate's yield buys a shared `write(2)` |
| 6–9 | Nits | `note_batch` before the parse loop; doc wording; a test comment's reason; a test name | **Fixed** |

Confirmed correct: execution timing, reply bytes and order, the AOF gate, the per-batch frame count on every path, cancellation, no shared hot-path state, the overflow arm, and the absence of flakiness in the tests.

**Round 2** (`6e57aad`). No Critical, High or Medium.

| # | Severity | Finding | Resolution |
|---|---|---|---|
| 1 | Low | The doubling back-off settles at 1,024 whenever probes gain less than ~29% of the time, e.g. 3 workers with a handful of P=1 clients | **Fixed**: escalate only for a worker serving one connection (`note_batch(conn_id)`, `company`) |
| 2 | Low | Recovery when load returns is bounded (≤ 1,024 flushes per worker, a few ms) | Documented in the code |
| 3 | Low | No test for `partial_left`, nor for `note_batch` counting only batches that ran a command | **Fixed**: a leading-split case and a no-command-batch test, each killing its mutant |
| 4 | Low, limit | A pipeline split exactly at frame boundaries (one `write(2)` per command) still yields | Documented as a known limit, as in 6O-B |

The reviewer confirmed `pipeline_tail` cannot get stuck in a harmful state, after tracing every split.

**Round 3**: the company guard was reviewed together with the round-2 items above. No further findings.

**Round 2** (`5f6c0fc`). No Critical, High or Medium. The reviewer confirmed:

## C3 TCP split (#160)

One round (`edf8519`), against the tokio 1.54.1 source; the reviewer also ran tests (`tcp_owned_split` 6/6; 44 lifecycle tests).

No Critical, High or Medium. Confirmed: every exit path closes the socket at the same point and in the same way as `tokio::io::split`, a `close()` when the last reference drops, with no `shutdown(Write)` first. That covers:
- EOF, read errors and protocol errors;
- QUIT and AUTH disconnect;
- the overflow arm, the WATCH/EXEC breaks and write errors;
- buffer overflow and pub/sub `None`.

Also confirmed:
- `forget` releases the `Arc`, so nothing leaks;
- delegation in `TcpWriteHalf` is exact;
- socket options survive the split;
- no cancellation hazard;
- TLS, WebSocket and replication are untouched;
- the EOF test is sound and not flaky.

| # | Severity | Finding | Resolution |
|---|---|---|---|
| 1 | Low | The read half is now a parameter and drops after the locals, so the connection guard (`CLIENT LIST`, active count) drops before the close. Harmless, arguably better | Documented |
| 2 | Low | No test runs `tokio::io::split` over a real socket now; no end-to-end TLS test exists (pre-existing) | Recorded; the duplex tests still cover the generic path |
| 3–5 | Nits | Unreachable `NotConnected`; a wrong comment on `drop(writer)`; what the half-close test guards | **Fixed** |
| 6 | Pre-existing | A close with unread input sends RST, so the last reply can be lost | Recorded |

## C4 MSET design

One round. Verdict: **APPROVE WITH CHANGES**, all applied (`V0.6O-C-MSET-DESIGN.md` §13).

Confirmed:
- MSET-pair ≡ SET default;
- per-pair telescoping;
- lock order, and no late failure;
- AOF, replica and MULTI unaffected;
- the reader non-atomicity claim, which is pre-existing.

| # | Severity | Finding |
|---|---|---|
| 1 | High | Per-pair `set()` would add a clock read and a reply allocation per pair; use `mset`'s own loop body |
| 2 | Medium | Borrowed-pairs-only signature would copy values on AOF replay |
| 3 | Medium | (B) borrowed MSET needs a multi-key accounted entry; reorder to (A) then (B) |
| 4 | Medium | The "stripes per pair" mutant survives the planned tests; add all-or-nothing final-state tests |

Lows and nits covered the `!enforce` condition (capped followers), the reader wording, the cycle-estimate basis and deterministic expired-key construction.

**The design requires the maintainer's approval before implementation.** It has not been implemented.
