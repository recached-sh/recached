## What 6O-B left

6O-B's yield ran before every flush that had replies, unless the worker was backed off. Its release gate recorded three costs (`../6o-b/V0.6O-B-RELEASE-GATE.md`, B3):
- MSET P=16 p99 +11% at 1 worker;
- SET P=16 p99 +26% at 3 workers;
- +3% CPU per op for one client on 3 workers.

It attributed the last to resumes on another worker scored as neither gain nor miss.

## The changes

| # | Change | Why |
|---|---|---|
| A | A flush yields only after a read batch that ran **exactly one command**, that leaves **no partial frame** behind, and that does **not complete a frame an earlier batch of commands left behind** (`pipeline_tail`) | A batch of pipelined commands already sends its replies in one `send(2)`, and its client is waiting for the whole batch, so the yield only moved the wait. The two partial-frame conditions catch a pipeline split by the 16 KiB read buffer, whose tail read completes one frame (review round 1, Medium) |
| B | `note_batch(conn_id)` is called only for batches that ran a command | A read that completed no frame was counted as company for other connections' yields (review round 1, Nit) |
| C | Back-offs **double**, 32 → 64 → … → 1,024 flushes, while the worker serves one connection; a gain, or a batch from a second connection, starts over at 32 | The one-client cost is the probes themselves: 2 yields per 34 flushes, each a scheduler round trip that can wake an idle worker. The company guard keeps 6O-B's fixed back-off for a worker with a few clients whose probes gain less than ~29% of the time (review round 2) |
| D | A yield that resumes on another worker stays **neutral**, as in 6O-B | The first commit scored it as a miss. The review (round 1, Medium) and the counters below show a lone task never migrates during its yield, while in the busy case 30% of yields migrate after gaining. Scoring them as misses backed the thief off |

Known limit, documented in the code: a client that writes each pipelined command with its own `write(2)`, to a server that keeps up, is read one whole frame at a time. Nothing distinguishes that from P=1 without timing, so it still yields, as in 6O-B.

Unchanged:
- when commands execute, and the reply bytes and order;
- the AOF gate path: a flush with AOF tickets queued still goes through `AofGatedWriter` and its own coalescer, whose algorithm is untouched;
- the overflow arm;
- the WebSocket handler.

## Measurements

All runs are native on the 6O-B host. Base is the pinned 6O-B binary (`d5563d7`, sha256 `9e845ff4…`). "C1" is `554dd7c` (sha256 `8c6b8852…`); "off" is the same binary with `RECACHED_REPLY_COALESCE=off`. Cells run 25–55 s. Medians are of 3 interleaved repetitions (5 for the 3-worker cells). Raw data is in `fedora-i5-9400f-20261122-v1/c1v2-*`.

Counts are the measured window only (after-minus-before). The base build counts a migrated resume as a gain in `gains`.

What they show:
- **A lone connection never migrated during its yield.** The 6O-B explanation of its +3% (migration not scored) was wrong. The cost was the 5.9% of flushes that probed, now 0.2%.
- **In the busy multi-worker case 30% of yields migrate.** Scoring them as misses, as the first commit did, would have backed busy workers off. Neutral is right.
- **Pipelined batches no longer yield at all;** at P=1 every flush still does and nearly every yield gains.

Instructions or cycles per op, client wake-ups (generator sleeps) and RSS for every cell are in the run summaries (`summary.md`). RSS is unchanged (26–27 MiB).

## The trade-off (maintainer decision)

At 1 worker the yield after a pipelined batch was buying throughput, not only costing tail:
- SET P=16: +9.6% over `off` (−8.7% for C1 against base);
- SET P=4: +6.2%;
- MSET P=16: +4.3%.

It cost 0–8% at p99. C1 gives the throughput back to get the tail back. At 3 workers the cost is −2.3%, and P=1, the primary gate, is untouched. C1 at P=16 is still 1.07× Redis (SET).

| Option | P=16 / P=4 throughput at 1 worker | P=16 tail |
|---|---|---|
| **C1 as is (recommended)** | Coalescing-off level, pre-6O-B behaviour for pipelines | Removed (MSET p99 −7%, SET 3-worker p99 −13%) |
| Revert change A only | 6O-B level | 6O-B's regression stays (B3 condition) |
