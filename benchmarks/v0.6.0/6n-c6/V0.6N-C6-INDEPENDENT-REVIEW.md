## PR 2: byte-sized replica queue

### Findings

| ID | Severity | Finding | Resolution |
|---|---|---|---|
| **M1** | **Medium** (pre-existing; made larger) | `fan_out` unregisters a replica whose queue is full but does not close its connection. The sender keeps draining what was queued into a socket the peer may never read, with no timeout. It holds the task, socket, connection permit and **up to the whole byte budget**, which none of `queue_bytes`, `queue_depth` or `connected_replicas` shows, until the peer reads or TCP gives up (about 15 min for a dead peer). The reviewer's scratch test: 3 s after unregistering, `pending_bytes` was 8,387,683. Before 6N-C6 the 4096-frame cap kept this to about 0.5 MB for small writes; now it is 8 MiB. The new docs' "disconnected" was therefore untrue. | **Fixed (`c32009f`).** The socket is wrapped in `Registered` once the replica registers. Dropping the handle makes every write fail at once, and a write already pending on a full socket is woken to fail. The sender returns and everything is released. The replica resumes from what it applied. Test: `an_unregistered_replica_that_keeps_its_socket_open_is_closed` (the sender ends within 10 s, nothing stays charged, and the peer finds the stream closed). Mutant: `unregistered-never-closed`. |
| L1 | Low (test) | Scenario F's reader could block forever: if it read the last frame before the test stored `stop`, it waited for a frame that would never come, and `reader.await` had no timeout. | **Fixed.** Every reader is awaited through `finish`, with a 60 s timeout. |
| L2 | Low (docs) | The `recached_replication_queue_bytes` gauge now includes the per-frame charge, but it was still documented as "encoded bytes", so dashboards would jump. | **Fixed.** `operations.md` and the CHANGELOG upgrade notes now say so. |
| L3 | Low (test gap) | The `RECACHED_REPL_BUFFER` parsing in `main.rs` was untested. A mutant that ignores an explicit cap there would survive. | **Fixed.** `parse_repl_frame_cap` is unit-tested: unset, a positive value, padded, `0`, negative, unparsable, empty, and huge. |
| N1 | Nit | "Bounds the queue's memory" is approximate: allocator rounding above about 256 B payloads, the tokio block at about 40 B per slot, the `BufWriter` and the kernel buffers. | **Fixed.** The docs say "to within the allocator's rounding … (at most about a quarter)" and list what is outside the budget. The code comment's slot size is corrected. |
| N2 | Nit | A byte budget ≤ 128 B refuses every frame. | **Fixed.** A startup warning. |
| N3 | Nit (pre-existing) | An unusable `RECACHED_REPL_BUFFER` falls back silently, and a value above tokio's permit limit panics each replica task. | **Fixed.** A warning, and clamping to `usize::MAX >> 3`. |
| N4 | Nit (test strength) | Several assertions cannot fail, because `fetch_update` enforces them or the workload fits even with an idle sender. The unauthenticated test fanned out only after both peers had closed. | The unauthenticated test now holds a peer **mid-authentication** while 100 frames are fanned out, and checks that no queue exists. The always-true budget checks remain as documentation of the invariant; the reviewer agreed they are harmless. |
| N5 | Nit | "On every run" in the CHANGELOG; `record_wake` can read cap + 1 on several workers; the sync counters count before the snapshot's writes succeed. | The CHANGELOG now says "10 of 10 runs of the reproduction". The other two are metric semantics and match the existing Prometheus counters. **Not changed**, recorded here. |

### What the reviewer confirmed

| Guarantee | Finding |
|---|---|
| Byte accounting | The charge is reserved before `try_send`. A refusal by bytes reserves nothing. A refusal by frames or `Closed` releases the charge through the returned frame's `Drop`. A saturated charge is never admitted. |
| Frame cap | The derived cap is budget / 128, clamped, so the bytes limit is reached first. An explicit cap is exact. `main.rs` passes the same budget to the channel and to `configure_queue_bytes`. tokio's channel reserves nothing up front. |
| The primary never waits | `fan_out` only `try_send`s under a synchronous lock, confirmed by scenarios E and F (and since M1, the connection lifetime too) |
| Isolation between replicas | Each replica has its own `pending_bytes` and budget |
| Ordering, no loss or duplication | Unchanged: offsets are assigned under the stream lock and frames are sent FIFO. The tests verify contiguous delivery, an exact partial resume, a full resync once the backlog has moved on, and the live stream continuing from the boundary. |
| Synchronization | Registration still happens under `lock_all_writes`, and the counters are on the right branches |
| Authorization | A queue exists only after authentication, the DEDUP capability check and a valid resume request |
| Untouched | DEDUP envelopes, promotion, AOF-before-fan-out, `RoundEnd` |
| Scheduler | The root-cause comment matches tokio 1.54. The queue peak at the default cap was 2,944–4,608 frames, against the asserted ≤ 10,240. Since 4,608 > 4,096, the old cap fails the regression in most runs. |
| Determinism | 25 module runs pinned to 1–2 CPUs, plus 40 more of scenario F on 1 CPU, all passed. The explicit-4096 test overran in 9 of 10, so both of its branches ran. |

## PR 3: cancellation-safe ACK read

### Findings

| ID | Severity | Finding | Resolution |
|---|---|---|---|
| **T1** | **Low** (flaky test) | `acknowledgements_only_ever_advance` asserted the acknowledged offset after a fixed 50 ms sleep. Under heavy oversubscription (32 parallel copies on 6 cores) it failed once in 96 runs, seeing `[0, 10, …]`. | **Fixed.** Steps where the value must rise now wait for it. Only steps where it must *not* move use the settle delay, where a slow sender can only make the test pass wrongly, never fail wrongly. |
| T2 | Nit | Tests 1, 4, 5, 6 and 8 pass on the old `read_exact` code. | By design: they check multi-ack parsing and unchanged behaviour. The reproductions are tests 2, 3 and 7, which fail on the old code (confirmed by the reviewer: test 2 holds `100 << 40`). No change. |
| T3 | Nit (coverage) | Every test runs over `tokio::io::duplex`; none over TCP or TLS. | **Added.** `a_partial_acknowledgement_survives_over_tcp` runs test 2's scenario over a loopback `TcpStream`. TLS was verified by reading the source (below). |

### What the reviewer confirmed

| Guarantee | Finding |
|---|---|
| Cancel-safety | tokio 1.54.1's `Read` future polls `poll_read` once: it either returns data or returns Pending having consumed nothing. `ReadHalf` passes the call through under its lock. For TLS, tokio-rustls 0.26.4's `poll_read` fills, copies and consumes within one poll, and plaintext not yet handed out stays in rustls's buffer. In `select!`, a read that returned Ready is always the winner. **No byte can be lost or counted twice.** |
| `AckReader` | At most 7 bytes are kept, so `spare()` always has at least 57 bytes and a spurious `Ok(0)` cannot happen. No index can go out of bounds. Alignment survives any sequence of partial reads. The highest ack per read followed by `fetch_max` gives the same result as handling them one by one. |
| Wire format | Unchanged. The replica's post-sync `boundary` write is also 8 bytes and is read as the first acknowledgement. |
| Consumers of the acknowledged offset | Only `max_lag_frames`, which feeds INFO `lag_frames` and the gauge. There is no `WAIT`, and neither failover nor backlog trimming reads it. |
| A malicious replica | Acknowledging `u64::MAX` hides its own lag (it reads 0, saturating). This is pre-existing, and it can neither panic nor affect others. Floods are read 64 bytes at a time, and `select!` order is random, so frames are not starved. |
| EOF, shutdown | `Ok(0) \| Err(_) => break`, as before. A partial ack at EOF is discarded. There is no busy loop. `RoundEnd` and the frame branch are untouched. |
