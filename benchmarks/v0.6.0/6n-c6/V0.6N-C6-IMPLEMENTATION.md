# v0.6.0 Phase 6N-C6B: byte-sized replica queue

**Branch:** `fix/v0.6n-c6-replica-backpressure` (PR 2). Its commits are the change (`bd48393`) and the review follow-ups (`c32009f`).

**Design:** [Option B](V0.6N-C6-BACKPRESSURE-DESIGN.md), approved by the maintainer on 2026-11-20.

**Scope:**
- `server-native/src/replication.rs`: the charge, the capacity, `Registered`, and the counters.
- `main.rs`: configuration.
- `info.rs`: four `INFO` fields.
- Tests, docs and the CHANGELOG.

**Unchanged:**
- The sender's scheduling (`RoundEnd`, batching).
- Offsets, the backlog, synchronization, DEDUP, promotion and AOF ordering.
- The wire and persistence formats.
- `RECACHED_AOF_FANOUT=inline` is still the default.

## What changed

| Piece | Before | After |
|---|---|---|
| Charge per queued frame | `bytes.len()` | `repl_queue_charge(len) = len.saturating_add(128)` (`REPL_QUEUE_FRAME_OVERHEAD`) |
| Byte budget | `RECACHED_REPL_BUFFER_BYTES`, 8 MiB, payload only | **The same variable and default**, now charging payload plus 128 |
| Frame cap | `RECACHED_REPL_BUFFER`, or 4096 | `repl_channel_capacity(explicit, bytes)`: the explicit value exactly, or else `bytes / 128` clamped to [1, 1,048,576]. That is **65,536** by default. |
| Parsing `RECACHED_REPL_BUFFER` | inline in `main.rs`; an unusable value fell back to 4096 silently | `parse_repl_frame_cap`: a positive integer, clamped to tokio's permit limit (`usize::MAX >> 3`, above which `mpsc::channel` panics). An unusable value logs a warning and falls back to the derived cap. |
| Byte budget below one frame | small frames still fitted | a budget ≤ 128 B logs a startup warning: no frame can fit |
| An unregistered replica's connection | `fan_out` dropped the handle. The sender then drained everything still queued to the socket, with no timeout, so a peer that stopped reading kept the task, socket, permit and queued frames (review M1). | The socket is wrapped in `Registered` once the replica registers. When the handle drops, every write fails, the sender returns, and everything is released. |
| `INFO replication` | — | `recached_replication_send_queue_bytes_peak`, `_queue_disconnects`, `_syncs_partial`, `_syncs_full` |
| Startup log | `… per-replica queue=<bytes> bytes / <frames> frames` | the same, plus `(derived from the byte budget)` or `(RECACHED_REPL_BUFFER)` |

## Data structures

- **`ReplicaHandle`** gains `_link: oneshot::Sender<()>`. It is never used for sending; dropping it resolves the matching receiver.
- **`Registered<S>`** holds the replica's socket and that receiver.
  - `poll_write` and `poll_flush` first poll the receiver. If it has resolved, they fail with `ConnectionAborted`. Otherwise its waker is registered, so a write that is pending on a full socket wakes and fails as soon as the handle drops.
  - `poll_read` and `poll_shutdown` pass straight through.
  - After the receiver resolves it is no longer polled, because a completed `oneshot::Receiver` must not be polled again.
- **`QueuedReplFrame`** is unchanged: `charged_bytes` now includes the overhead, and `Drop` releases exactly that.

## Resource accounting

| Step | Code | Invariant |
|---|---|---|
| Reserve | `fetch_update(checked_add(charge), ≤ max_queue_bytes)` | Never exceeds the budget. A charge that saturates to `usize::MAX` can never be admitted. |
| Refused for bytes | Nothing is reserved | The replica is dropped (`queue_disconnects` +1, `disconnects_total{queue_bytes}`) |
| Refused for frames (`Full`) or `Closed` | The `QueuedReplFrame` returned inside `TrySendError` is dropped, which releases the reservation | The accounting matches what is queued (tested) |
| Sent | `Drop` after `write_repl_frame` copies it into the `BufWriter` | Released exactly once |
| Sender aborted or ended | Dropping the receiver drops every queued frame | Fully released (tested with frames still queued) |
| Replica unregistered | `_link` drops, `Registered` fails the next write, the sender returns, and its receiver and socket drop | Released without the peer's cooperation (tested: `an_unregistered_replica_that_keeps_its_socket_open_is_closed`) |

## Memory bounds (per replica, default configuration)

- **Items:** at most 65,536, and at most budget / 128.
- **Charged bytes:** at most 8 MiB.
- **Real heap the queue holds:** about 8 MiB. Per queued frame that is a slot of about 40 B, an `ArcInner` of 48 B, and the payload rounded to its jemalloc class. This is under the 128 B charge for payloads under about 256 B; above that, rounding adds at most about 25%. As before 6N-C6, a `Vec`'s spare capacity is not charged: DEDUP envelopes can hold up to about twice their length.
- **Outside the budget, as before:** the 64 KiB `BufWriter` and the kernel socket buffers.
- **Since M1:** an unregistered replica holds none of this beyond the moment its sender is next polled.
- **N replicas:** N × the above, plus the shared 16 MiB backlog. N is bounded by the listener's connection permits.

## Behaviour after a disconnect

A replica unregistered for a full queue now receives at most a contiguous prefix of what was queued, possibly with a final frame cut off, and then the connection closes. Before, it received the whole queue, if it read. It reconnects and resumes from the last frame it applied. The replica reads whole frames before applying them (`read_repl_frame`), so a truncated frame is never applied. `small_explicit_channels_…` and `pipelined_rounds_against_an_explicit_4096_frame_cap_lose_nothing` check that the resumed stream is exactly the rest.

## Rollback

- Operational, with no code change: `RECACHED_REPL_BUFFER=4096` restores the old frame cap. The overhead charge and the M1 close remain; both only make the queue stricter.
- Code: revert PR 2. Nothing persistent, and nothing on the wire, depends on it. The `INFO` fields simply disappear.
