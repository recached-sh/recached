# v0.6.0 Phase 6O-E: independent review

## How the reviews were run

- **Reviewers.** There were two reviewer agents, one per change set. Neither wrote any of the code. Each worked read-only on its own detached worktree and Cargo target directory.
- **What they were given.** The diff, the surrounding code, the Redis 7.2.5 requirements, the brief's invariants and the specific attack list. They could build probes and run Redis. They were **not** given the author's correctness argument.
- **What they were asked.** To build adverse schedules, and to name wrong implementations that the tests would pass.
- **Follow-ups.** Follow-up commits went back to the same reviewer.
- **Scratch material.** Probe code, patches and mutant logs are in the session scratchpad and in `~/recached-6oe-bench/review-e1-*`. The probes that found defects became permanent tests.

## E1: EXEC isolation (`66e6293` → `282f05a` → `43dfec5`)

### Round 1 (`66e6293`): APPROVE WITH CHANGES

Confirmed correct:
- **Lock order.** Gate, then stripes in ascending order: no inversion with the watch registry, pub/sub, AOF or store stripes. The store's `std::sync` stripes are never held across an await.
- **No bypassing write path.** Every write path is excluded by the gate and the stripes: unordered, borrowed (it re-checks after its pre-check), ordered, DEDUP, ESET/EADD, replica apply, capped and evicting stores, active expiry, snapshot, promotion, full sync, QSUB and ephemeral release. Reads only mask expired keys.
- **Classification is complete.** Every `is_write_command` variant has its keys in `primary_key_refs`/`ordering_key_refs`, and reads are covered by `read_keys`. The oracle's sample keys hash to distinct stripes, so a collision cannot hide a miss.
- **WATCH keys stay in scope.**
- **Cancellation and the clock.** Guards and `GateClosed` are RAII. `at_instant` takes a synchronous `FnOnce`, cannot span an await, nests, and is restored on unwind.

## E2 and E3: WATCH (`d9a92c7`/`4a68ca2` → … → `76142e8`/`9d07c23`)

### Round 1 (`4a68ca2`): REQUEST CHANGES

| # | Sev | Finding | Resolution |
|---|---|---|---|
| 1 | **High** | "No change" for a key absent at WATCH was decided by reading the key when the notification was delivered, after the write's AOF stage and outside the transaction's instant. A key created with a short TTL had expired by then, so the watcher missed its creation and committed. Probes: 20/20 commits with `appendfsync always`, 9/200 without AOF, and deterministic inside a stopped transaction. Redis 0. **A regression of the first E2 version** | **Fixed** (`45302e0`): every write that sets a key invalidates; removals are decided by the command (DEL/UNLINK announce removals); no store read. Probes became tests |
| 2 | Medium | Creating an absent key already expired (`PXAT 1`) was "no change"; Redis aborts | **Fixed** by the same change. Test and differential case |
| 3 | Low (test gaps) | Surviving mutants: partial UNWATCH clearing the flag, EXECABORT leaving it set, WebSocket never setting it (equivalent) | **Fixed** (`d7df212`→`9d07c23`): tests for the first two; the third recorded as equivalent |
| 4 | Low | The replaced 6O-B test's comment overstated its coverage | Fixed |
| 5 | Nit | A dead connection's registration lingers until the next write to its key | Same as before E3. Recorded |

Confirmed correct in round 1:
- **The flag's clear sites.** All 15 run after unregistering. The flag is per connection, and re-WATCH keeps its first liveness, as Redis's `watchForKey` does.
- **WebSocket gate claim.** A socket that can WATCH is a counted push receiver: strict sockets need a token, and AUTH and SYNC TOKEN route it with the gate closed.
- **E3 bounds.** A TCP watcher queues and charges nothing, and no TCP path disconnects a WATCH-only client.
- **Changed #157 tests.** Each is justified and still asserts no commit. The CAS stress showed 0 violations in 3,000 rounds.

### Round 2 (`d7df212`): APPROVE WITH CHANGES

Round-1 High and Medium were confirmed fixed (P3 0/20, P4 0/200). The reviewer agreed that the #157 check is now defence in depth.
