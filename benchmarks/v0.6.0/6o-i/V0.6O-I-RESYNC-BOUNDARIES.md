## 1. Definitions (replica)

| Term | Meaning | Where |
|---|---|---|
| last received | highest offset read from the link; may be inside a group | `GroupAssembler` |
| last applied / last committed boundary | `ReplResume::offset`: advanced only after a lone frame or a whole group has applied and its effects are queued | `sync_from_primary` |
| last acknowledged | written when nothing more is buffered: ≤ the committed boundary, never inside a group | streaming loop |
| resume point | the committed boundary, in the next handshake, offered only in the same `expirylog1`/`txn1` mode | `ReplResume` |
| backlog retention boundary (primary) | the oldest retained offset; partial needs every missing offset | `resume_frames` |

## 2. Rules and their evidence

| Rule | Evidence |
|---|---|
| 1. A capable replica resumes and acknowledges only at committed boundaries | by construction; `a_link_that_ends_inside_a_group_applies_none_of_it_and_resumes_before_it`, `a_replica_that_applied_a_group_resumes_after_it` |
| 2. The primary answers a `txn1` replica's mid-group resume with a full sync | `a_capable_replica_never_resumes_inside_a_group` (the design's worked example, below); `a_real_primary_answers_a_resume_inside_a_group_with_a_full_sync` (partial/full counters asserted per resume point) |
| 3. A legacy replica resumes anywhere, as before | the same two tests |
| 4. The full-sync and partial-sync boundaries are never inside a group | `fan_out_group` advances the offset by `count` in one step under the stream lock; the handshake's barrier excludes `EXEC` phase 2 and a replica's group apply; a partial sync that ends with the assembler open is a protocol error |

## 3. The worked example (required by review D)

Group G = offsets 101–103, behind 100 single frames.

| Request | Backlog | Answer |
|---|---|---|
| capable, resume 100 | all retained | partial: 101–103, header first |
| capable, resume 101 or 102 | all retained | **full** (rule 2) |
| capable, resume 103 | all retained | partial, nothing missing |
| legacy, resume 101 | all retained | partial: 102–103 (rule 3) |
| after trimming to begin at 102 | capable, resume 103 | partial: 104 |
| | capable, resume 100 | full (101 gone) |
| | capable, resume 101 | **full** (rule 2: 102–103 would be a fragment) |
| | legacy, resume 101 | partial: 102–104 |

Review D reproduced it on a real primary with the real `sync_from_primary` (a replica handed `ReplResume{run, 2}` inside a group took one full sync and converged), and tried backlog trims, `reset_stream`, `requested == current`, lock-free offset readers, concurrent `fan_out`/`fan_out_group`, a queue-full cut, read-ahead during a full sync, a replica that applied frames before negotiating `txn1`, and promotion while assembling: no mid-group resume got past rule 2.

## 4. Slow replicas, chains, promotion, restart

| Case | Test |
|---|---|
| a replica whose queue overflows on groups (4 KiB queue, 40-member `EXEC`s): it is disconnected, resumes partially from the backlog, and converges; its readers never see part of a transaction | `a_replica_whose_queue_overflows_on_groups_resumes_and_converges` |
| a link that ends inside a group (deterministic, fake primary) | PR 3's `a_link_that_ends_inside_a_group_…` |
| disconnect after a group, before its acknowledgement | `a_replica_that_applied_a_group_resumes_after_it` |
| A → B → C: A's stream reset; B full-syncs and resets its own; C full-syncs; a key deleted meanwhile is gone on both | `a_middle_replicas_full_sync_resets_its_sub_replicas_and_they_converge` |
| B promoted: its stream and C's link continue; B's transaction reaches C as one group | `a_promoted_middle_replica_keeps_grouping_for_its_sub_replicas` |
| B restarted | its in-memory resume point is gone: full sync, which resets its stream, so C full-syncs (6O-G, unchanged) |
| a group that fails on B, B promoted first | `a_failed_group_on_a_middle_replica_resets_its_sub_replicas` (PR 4) |

Correctness over avoiding full syncs: every uncertain case takes one.
