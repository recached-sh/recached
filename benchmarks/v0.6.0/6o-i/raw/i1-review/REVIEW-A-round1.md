# Review A, round 1: `V0.6O-I-PROTOCOL-DESIGN.md` revision 1

Reviewer: independent (did not write the design). Base checked: `recached-6oi-design` at `dev` `6068337`, unmodified.
Probes: `probe.py`, `probe2.py`, output `probe-out.txt` (same directory), run against the real binaries in `~/recached-6oi-bench/bin/`.

## Verdict: **APPROVED WITH CHANGES**

The core mechanism holds up. Groups are contiguous in the AOF (one queue-lock hold) and in the offset space (one stream-lock hold). The authorship argument for the must-understand `txn` bit is real (reproduced, P4). Incomplete tails are cut before any append. Rule 2 plus per-frame extents close the mid-group resume. I found no Critical or High finding.

Four Medium findings must be fixed in the design before PR 2/PR 3:
- two contradict 6O-H's binding ignorable/authorship rules, or leave them ambiguous, so a legitimate file can be refused;
- one is a false "history is never silently dropped" claim, with two byte-level counterexamples on real binaries;
- one is an under-counted memory bound.

## Verified as correct (against the code at `6068337`)

**AOF**
- `EXEC` is logged in one AOF batch through every path: `on_transaction_logged` → `append_frames`, `append_coalesced_frames` or `append_client_writes`, each `push_frames` inside one `queue_only`/`enqueue` edit under one queue-lock hold.
- A checkpoint marker can therefore never land inside a group, whatever the stripes.
- The checkpoint and snapshot are taken under `save_lock` plus `lock_all_writes`. `EXEC` holds `_write_guards` through phase 2 on both TCP and WebSocket (`connection.rs` ~916, ~2101).
- The sweeper queues under the barrier. The seed is appended after `truncate_then` has waited for its batch. Startup discards are appended before any listener.
- Startup order: `replay_aof_format` (which cuts its torn tail with `set_len` + `sync_all`) runs before `start_expiry_log`'s first append. A failed cut fails the start.
- Control ids are right: `FORMAT(expirylog,txn)` = 17005593296757653505; `TXN-BEGIN 2` = 17005734034245943298; `TXN-COMMIT 2` = 17005735133757571074. Every record is 57 bytes, including with payload `u32::MAX` (20 digits).
- `is_control_id` keeps them out of `replay_start` and out of checkpoint ids.
- 6O-H code treats bit 16 as an unknown must-understand bit (`format_is_timeless`), so it replays legacy and appends pushes (T5b/T5c).
- The A1 rationale is reproduced (P4): 6O-H appends `*` arrays after a dangling group in a `FORMAT(expirylog)` file.

**Replication**
- Today's `fan_out` takes the stream lock per frame and assigns `offset` inside it.
- `handle_replica` reads the boundary, takes the backlog via `resume_frames`, and registers the sender under the all-write barrier, so the backlog/live boundary is never mid-group.
- With extents on every backlogged frame, rule 2 closes mid-group resumes. I could not construct a deterministic mid-group resume that is not rejected:
  - the resume point is always the full-sync boundary, the partial-sync boundary, or a committed group end;
  - `ReplResume` is in memory, so a restart takes a full sync;
  - `reset_stream` rotates the run id.

**Replica apply**
- A replica's store is a follower from startup (`main.rs` ~774), so `enforces_caps` is false and `hold_transaction` takes only key stripes. `apply_transaction` wraps every member in `at_instant(now)`. `upstream_expirylog` selects `without_expiry`.
- `apply_repl_frame` turns a failed command into `InvalidData`, which clears `ReplResume` and forces a full sync.
- Promotion takes the barrier, so it excludes a group's apply.

**Limits, handshake and baseline**
- Limits: run-id string 40 + 28 = 68 B and the accept string 70 B, both within the 128 B limit on both sides. `HandshakeId::has` splits on `,`. 0.5 echoes `caps=…`, never `accept=`. `REPL_QUEUE_FRAME_OVERHEAD` = 128. `MAX_REPL_FRAME_BYTES` = 512 MiB. Read-ahead 64 + 64 MiB.
- Acks are used only for lag: there is no `WAIT`.
- The baseline reproductions (34/68 cuts; 274 part-applied reads) are consistent with the code paths described in `V0.6O-I-BASELINE.md` §2.

## Not verified

- No 6O-I code exists. Group-aware `cut_back`, pass-1 classification, `fan_out_group`, the assembler and `Timeless{txn}` mode transitions are reviewed as specification only.
- Real power-loss ordering (ext4/XFS writeback, holes after a runtime `cut_back` followed by re-append). I did not test it; the design states garbage is refused "as today".
- `size_of::<Command>()` and the exact allocation overhead behind the M4 estimate (estimated, not measured).
- `Value::parse` behaviour for every malformed prefix (only the cases above were exercised).
- Behaviour of 6O-F/6O-G/0.5 replicas against a `txn1`-advertising primary. Static reading of `HandshakeId::has` says it is fine, but PR 3 must repeat review C's fake-primary check.
