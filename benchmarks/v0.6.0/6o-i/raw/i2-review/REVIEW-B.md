## Torn-write counterexample attempt

Goal: after any sequence of faults, crashes and restarts, the recovered keyspace holds part of a group's records, or the file ends inside a group that a later append follows. **Outcome: I found no counterexample.** What I tried:

| # | Sequence | Why it cannot tear a group | Evidence |
|---|---|---|---|
| 1 | `write(2)` fails part-way through a group, under any policy | `cut_back` → `whole_frames_len` keeps only frames outside an open group. With `torn = written − keep > 0`, the file is cut to the group's `TXN-BEGIN`. A batch that is a run of groups and singles keeps each complete group and each whole single | PR unit test, plus probe **P3**: three appends in **one** batch (group, single, group), torn at every one of 642 byte offsets. In every case: no group partly present, the single kept only when whole, the next append replays cleanly |
| 2 | The cut fails (`torn_at` set), then retried | `remove_torn_fragment` runs before any later write and truncates to the `TXN-BEGIN` offset (`len − (written − keep)`), or fails the batch. | 3 | The file cannot be measured (`TORN_AT_UNKNOWN`) | No append until a truncation, which resets the file and writes `FORMAT` | Read the code (cannot be injected) |
| 4 | `fdatasync` fails under `always` | `settle` → `fail_stop` before any waiter resumes (unchanged). On restart a complete group replays and an open one is cut | Existing gate tests pass |
| 5 | A crash or power loss at any byte | Pass 1 marks an open group at EOF or at a torn record as `discard_from`. Pass 2 stops at `replay_end`. The file is cut (a copy is kept first). ## What I verified

1. **Crash atomicity.** See the table above. `whole_frames_len`, `cut_back`, `remove_torn_fragment` and startup's `discard_from` together mean a `txn` file never gets an append after an open group from this server, and replay never applies part of a group.
2. **The §3.1 rows, in order.** Rows 1 and 2 (push, unknown non-ignorable kind) come first, then 3 (ignorable kind or non-head `FORMAT`), 4 (matching commit), 5 (nested begin, mismatched commit), 6 (array marker, DEDUP), 7 (member, overrun), 8 (EOF or torn, after the loop), and outside the group 9, 10 and 11. Groups are recognized only while `grouped_head && (open || timeless_end == MAX)`. §3.2: a complete group replays, an incomplete tail is copied (temporary name, fsync, rename, directory fsync, best effort) and then cut, an abandoned group replays one by one with a warning and a counter, and a corrupt group returns `InvalidData` with the file untouched.
3. **Corruption.** I found no silent acceptance beyond the §3.2/§3.6 limits, except F2 (no data loss). `is_flat_record` does not refuse any file I could produce: every current frame builder is `resp_push` of bulk strings, and DEDUP envelopes are flat. Files written by **v0.4.0, v0.5.1, v0.5.2, 410235b, f9a364d and 6068337** with a 40-command mix (strings, hashes, lists, sets, zsets, expiries, binary values, `MULTI`/`EXEC`, `EADD`/`ESET`) all replay unchanged and untouched (P1). The only refusal I found of a file that previously started is F3.
4. **fsync semantics.** `settle`, `fail_stop`, the gate and the deferral are unchanged. `no_reply_precedes_its_aof_write_under_any_policy` and the `always`/`everysec` failure tests pass. Under `everysec`, a failed group is now cut whole, where before 6O-I a prefix could survive. That is the intended change.
5. **Checkpoints.** `FORMAT(expirylog, txn)` is written in the truncation's own batch, under the same lock hold, with `author` and `grouping` set. A failure resets `mode` and `grouped` before the barrier is released. A checkpoint marker or snapshot cannot fall inside a group (barrier plus one lock hold), and an array marker found inside a group is refused.
6. **Legacy and 6O-H files.** `grouped` is true only for `Timeless` files whose head `FORMAT` passes `format_is_grouped`. A 6O-H file or a legacy file gets no groups until its checkpoint (`only_a_txn_file_gets_groups_until_its_checkpoint`), and its replay is unchanged apart from the nested-record refusal and the new `.cut-` copy. `TXN-*` records stay ignorable there.
7. **Regressions.** The full `recached-server` suite passes on the review copy: **832 passed, 0 failed, 11 ignored** (this includes my eight probes and the T4 test with the files present). The framing, 6O-H format, 6O-G transaction and probe tests pass under `RECACHED_AOF_FANOUT=coalesced` (86 passed). The 6O-H test edits (FORMAT id, the must-understand bit moved to 17 in one test) are correct. The `compat-matrix.sh` grep accepts both `FORMAT` ids.

## What I could not verify

- A real `TORN_AT_UNKNOWN` (`metadata()` failing after a partial write) and a real failing directory fsync: neither can be injected. Both were read only.
- Power-loss behaviour of the page cache (out-of-order writeback, holes). I relied on design §3.6: zero-filled holes give a parse error and refuse the start, unchanged.
- The release-build cost of F4. I estimated it from the code and did not measure it; design §10 defers measurement to PR 6.
- A process-level probe of a 6O-I binary built from this branch: I used in-process boots (`boot`, `Pipe`), as the PR's own tests do.
- Replication (`caps=txn1`) is out of this PR's scope. A replica's `txn` file holds no groups yet, which is consistent with the design.
