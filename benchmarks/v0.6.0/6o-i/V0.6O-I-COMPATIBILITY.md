## 1. Older binaries reading 6O-I files

| | v0.4.0 | v0.5.1 | v0.5.2 | 6O-F | 6O-G | 6O-H |
|---|---|---|---|---|---|---|
| a complete group | replays | replays | replays | replays | replays | replays |
| an incomplete tail group | prefix applied | prefix | prefix | prefix | prefix | prefix |
| `SAVE`, write, `SIGKILL`, restart | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| what it appends to a `txn` file | push | push | push | push | push | push |
| `FORMAT(expirylog, txn)` replay | legacy | legacy | legacy | legacy | legacy | **legacy** (must-understand bit) |

**Replaying frames one by one is not transaction crash atomicity.** An older binary gives a 6O-I file the recovery any file without framing gets.

## 2. 6O-I reading older files

`corpus_compat.py`: on each older binary, 77 write commands (strings, expirations, renames, `COPY`, hashes, lists, sets, sorted sets, ephemeral keys), one by one and again inside `MULTI`/`EXEC`, then `SIGKILL`, then the 6O-I binary on the same files. **14/14**: the 6O-I binary starts on every file (the nested-record refusal, D4, never refuses one) and recovers exactly what the older binary recovers from its own file. In one earlier run, v0.5.1's (and, in another, v0.5.2's) `MULTI`/`EXEC` corpus left its AOF different from what it served: its own restart recovered the same as 6O-I's. That is a pre-6O-G behaviour of 0.5 (6O-G fixed `EXEC` logging), not a 6O-I difference; the tool records it as `PRE-EXISTING` when it occurs.

| File | 6O-I replays | 6O-I then writes |
|---|---|---|
| no `FORMAT` (any release) | legacy, as before | pushes, no groups, until its first checkpoint |
| `FORMAT(expirylog)` (6O-H) | timeless (T5 on the 6O-I binary) | arrays, no groups, until its first checkpoint |
| `FORMAT(expirylog, txn)` | timeless, groups classified | arrays and groups |
| an older binary's records after a dangling group | abandoned group, one by one; nothing lost (the six real T4 files) | — |

## 3. The 6O-I binary on its own files (T1–T9)

| Case | Result |
|---|---|
| complete group | replays |
| incomplete tail group, a member torn or not | **none of it** (`['old','old']`), cut back |
| T4 (a dangling group, then writes) | the group cut before the first append, which is an array |
| `FORMAT(expirylog, txn)` | timeless |
| option C (`MULTI`/`EXEC` records), option B (composite) | refused, as by every binary |
| malformed group markers | **refused** (an empty or `u32::MAX` group): older binaries treat them as no-ops |

## 4. Downgrade and re-upgrade

| Path | Result |
|---|---|
| `SAVE` on 6O-I, stop, older binary (the documented procedure) | the groups are truncated away; the older binary sees `FORMAT` and its own records (T3) |
| …then writes, crashes, re-upgrade | its file is legacy (or 6O-H's `FORMAT(expirylog)`): 6O-I replays it by its rules; no step needed |
| a 6O-I crash, then an older binary started directly (outside the procedure) | the older binary applies the incomplete group's prefix and appends pushes; on re-upgrade the group is abandoned and replayed one by one, nothing lost. v0.4.0 after a torn member: re-upgrade refuses (nested record), never misapplies |
| `SAVE` on 6O-I, then 6O-H | 6O-H replays legacy until its own first checkpoint (D2) |

## 5. Replication

`repl_compat.py`, real processes, 200 eight-key `EXEC`s plus single writes and an `EXEC` on an expired key; a reader of the replica polls `MGET` of the eight keys:

| Primary → replica | Links and converges | Part-applied `MGET`s seen on the replica |
|---|---|---|
| 6O-I → 6O-I (`txn1`) | ✓ | **0** |
| 6O-I → 6O-H | ✓ | some (frame by frame, as before) |
| 6O-I → 6O-G | ✓ | some |
| 6O-I → 6O-F | ✓ | some |
| 6O-I → v0.5.2 (`RECACHED_REPL_DEDUP=off`, unchanged since 6B) | ✓ | some |
| 6O-H → 6O-I (no `txn1` offered) | ✓ | some |
| v0.5.2 → 6O-I | ✓ | some |

Counts per run are in the raw file (they vary with timing). A new primary does not break an older replica; only a capable pair gives atomicity on the replica.

## 6. Documented limits, unchanged

- Downgrade: `SAVE` first (unchanged procedure). Without it, an older binary gives a crashed file today's per-frame recovery.
- v0.4.0 refuses AOFs holding DEDUP records (pre-existing).
- A legacy or 6O-H file gains framing at its first checkpoint.
