## 1. Recovery outcomes

| File holds at the end | Outcome | Evidence |
|---|---|---|
| a complete group | all of it replays | `a_complete_group_replays_and_its_markers_are_skipped`; T1 (real binary) |
| `TXN-BEGIN` alone, torn or whole | nothing of it; cut back to `TXN-BEGIN` (copy kept) | `an_incomplete_tail_is_discarded_and_cut_back_to_its_begin`; every-byte cut test |
| `TXN-BEGIN` and some members, the last possibly torn | nothing of it; cut back | same; T2/T2b on the 6O-I binary: `['old','old']` (`raw/i6-compat/txn-compat-6oi.txt`) |
| all members, no `TXN-COMMIT`, or a torn one | nothing of it; cut back | same |
| a complete group then a crash | all of it | the every-byte test's last cut |
| an unknown group version (an unknown control kind or layout inside a group) | the group is abandoned (6O-H's rules for a later writer) | `later_writers_control_kinds_follow_the_6oh_rules_inside_groups` |
| unsupported feature bits (an unknown must-understand bit) | the file replays legacy and gets no groups (6O-H) | `aof_format_6oh::only_a_head_format_with_understood_features_makes_a_file_timeless` (bit 17) |
| an older binary's records after a dangling group | abandoned: members one by one, then the older records | six real T4 files, `the_files_older_binaries_left_replay_here` |
| a malformed group followed by valid-looking records | **refused** ("AOF corrupted at offset …") | `malformed_groups_refuse_the_start` |
| a torn record another server appended after (v0.4.0) | refused (nested record) | same |

**Corruption vs torn tail.** Only an open group (or torn record) at the end of the file with nothing after it but arrays (and one torn record) is treated as a tail. Anything followed by complete records is history: refused if malformed, abandoned if another server's pushes follow. A length corrupted mid-file is indistinguishable from a tail (pre-existing); every cut is now copied beside the file and logged.

## 2. Crash points

The every-byte test (`an_exec_cut_anywhere_in_its_records_replays_all_or_nothing`) cuts a transaction with an observed-expiry `DEL` (`SET a; APPEND x` on an expired `x`; `SET b`) at every byte, which covers:

| Crash point | Covered by |
|---|---|
| before `TXN-BEGIN` | cut at the transaction's first byte |
| inside / after `TXN-BEGIN` | cuts 1–57 |
| after the first member, between members, inside the expiry `DEL` | every member boundary and every byte inside |
| before / during `TXN-COMMIT` | the last 57 cuts |
| right after `TXN-COMMIT` | the uncut file |
| eviction `DEL` inside a group | `a_capped_exec_groups_its_eviction_dels_after_their_command` (placement) with the same classifier |
| `write(2)` failing part-way, at every group boundary | `a_failed_write_inside_a_group_is_cut_back_to_its_begin` (EverySec writer: the next transaction follows the last complete record) |
| `fdatasync` failure under `always` | unchanged fail-stop (exit 74) before any reply (`aof_fail_stop.rs`); a group whose fsync did not complete is a tail on restart |
| an unrepairable cut | review B probe P4: `TornUnrepairable` at every byte of a group, crash and retry |
| concurrent pipelined `EXEC`s | review B probe P2: 6 clients × 6 `EXEC`s, `always`, cut at every byte: every transaction all or nothing; also coalesced |
| checkpoint | the checkpoint holds the all-write barrier, which `EXEC`'s phase 2 excludes; a group is queued in one lock hold. `FORMAT(expirylog, txn)` goes in the truncation's batch. Crash windows as 6O-H §4.3 (`restarts_and_checkpoints_keep_grouping`) |
| replica acknowledgment | a replica acknowledges only a whole applied group (`V0.6O-I-RESYNC-BOUNDARIES.md`) |
| a replica restarted on its own incomplete tail | cut before its first append (`a_replica_restarted_on_an_incomplete_tail_cuts_it_before_appending`) |

Verified on the replayed **state**, not only on startup: every test compares values.

## 3. Power loss and the `fsync` policies

| Policy | Guaranteed | Not guaranteed |
|---|---|---|
| `always` | a transaction whose `EXEC` was acknowledged replays whole: its batch was written and `fdatasync`ed before the reply; a failure is a fail-stop before any reply | — |
| `everysec` | a recovered transaction is never partial | up to about a second of acknowledged transactions can be lost; a lost one is lost whole |
| `no` | the same | the kernel decides when anything reaches the disk |

A power loss that leaves garbage or zeroes inside the file's length (not a clean prefix) is a parse error and refuses the start, as today. Framing changes none of the policies (`AofSync`, the batch `fdatasync`, the fail-stop are untouched).

## 4. Replicas

A replica never applies part of a group: it buffers the group and applies it under one store hold, or not at all. A link that ends mid-group leaves the replica at the group's start (`a_link_that_ends_inside_a_group_applies_none_of_it_and_resumes_before_it`); one that ends after the group but before the acknowledgement leaves it after (`a_replica_that_applied_a_group_resumes_after_it`). A group that fails part-way (a diverged replica, a panic) is the one case where readers can see a part-applied group, until the forced full sync installs; the node meanwhile resets its stream and resynchronizes its clients (`V0.6O-I-REPLICA-ATOMICITY.md` §4).

## 5. Known limits

| Limit | Status |
|---|---|
| Length corruption mid-file looks like a tail | pre-existing; now copied and logged, not silent |
| v0.4.0 keeps a torn tail and appends after it | now refused on re-upgrade instead of misapplied (D4) |
| `TORN_AT_UNKNOWN` blocks `SAVE` (review A L3) | pre-existing liveness gap, follow-up in the release gate |
| A crash during the `.cut-` copy leaves a `*.partial.*.tmp` | documented; never under the `.cut-` name |
