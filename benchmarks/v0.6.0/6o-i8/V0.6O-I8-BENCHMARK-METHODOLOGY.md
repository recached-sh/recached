## 2. The driver: validity before numbers

Every run starts its own servers and ends them; nothing is reused between runs. Before a run, the driver waits (up to 30 min, else the run is **invalid**) until:

- no compiler (`cc1`, `rustc`, `cargo`, `ld`, `lld`) is running;
- the 1-minute load average is below 3.0;
- no Recached server, `txbench` or `i8bench` that this driver did not start is alive (any process whose executable is `rc-*`, `recached-server`, `txbench` or `i8bench`);
- every port of the run's block (8 ports, below 32768, so outside the kernel's ephemeral range `32768–60999`) can be bound on `0.0.0.0` and `127.0.0.1`. A busy port marks the attempt **invalid** (recorded with the port), and the run is retried once on the next block.

After a server answers `PONG`, `INFO server`'s `process_id` must be the pid of the child the driver started; otherwise another process owns the port and the run is **invalid**. Every child (servers, generator, perf) is started in its own session and process group; on exit, on any exception and on `SIGTERM`/`SIGINT`/`SIGHUP`, the driver kills exactly those groups (and writes `ABORTED`). A generator that exits non-zero, a server that dies, or a replica that never attaches makes the run **invalid** (it did not complete). A completed run is **comparable** only if every check passed (the replica converged; the primary matched the expected keyspace where there is one; the replica's digest, `DBSIZE`, TTL count and missing keys matched the primary's; the replica restarted from its own AOF matched) and, in a contention cell, its replica never disconnected or resynchronized (full or partial) during the load. Paired ratios use comparable runs only; every other run is listed in the summary with its reason (review A, M1). In the paced replica cells, disconnects and resyncs *are* the measurement and do not exclude a run.

Recorded per run, before and after: load average, governors, every CPU's current frequency, `MemAvailable`, `SwapFree`, `Dirty`, `Writeback`, PSI (CPU, I/O, memory) and `/proc/diskstats` for `sda`.

### The 1 Hz series (`series.jsonl`)

Each second, for the primary and the replica: `VmRSS`, `VmHWM`, `RssAnon`, `RssFile`, `RssShmem`, `VmSwap`, `Threads`, voluntary and involuntary context switches, on-CPU time (the sum of every thread's `schedstat`); `INFO replication` (offset, lag frames, queue depth, peak queue frames and bytes, queue disconnects, full and partial syncs, send flushes and frames); for a server with an AOF, its `recached_aof_*` counters (bytes, frames, `write(2)` calls and time, `fdatasync` calls and time); host CPU busy time, disk statistics, I/O and CPU pressure, memory. One INFO per server per second is extra load on the stream lock (`INFO replication` takes it), the same in every build.

### Phases of a run

1. Start the primary (and the replica, which attaches with its initial full sync), check ownership.
2. Prefill: `contend` cells use 6O-I's prefill unchanged (`redis-benchmark -n 300000 -c 20 -P 64 -r 100000 -d 32 -t set`); `paced` cells set every key `key:<i>` (`i < 100,000`) to `init:<i>` padded to 32 bytes. Wait for the replica to hold all of it (lag 0, queue 0).
3. Load: warm-up (not counted), then the measured window (`measure_start_ms`..`measure_end_ms`, from the generator). `perf stat` counts the servers during the measured window.
4. Drain: poll every 250 ms until the replica is attached, its lag 0 and the queue empty (`catchup_s`, bounded by `drain_max`).
5. Post-load window (`post` seconds, default 30–60 s), still sampled: memory after the load.
6. Verify (§3.3): the primary, the replica, and for a replica with an AOF, the replica again after `SIGKILL` and a standalone restart from its own files.

CPU per transaction is each server's on-CPU time, interpolated from the series to the generator's window, over the transactions completed in that window. `foreign_cpus` is every CPU's busy time minus both servers' and the generator's (the generator's from its `/proc/<pid>/stat` `utime + stime`, since its threads exit at the end of the window, which would empty a per-thread `schedstat` sum: review A round 2, N3; campaigns sampled before driver v2 fall back to `schedstat`).

## 3. The generator

### 3.1 `contend`: the large-transaction workload

The 6O-I campaign C cell, unchanged: 6O-G's `txbench setn unrelated` (the key pool `key:{i:012}`, 100,000 keys; per-client seeds `0x9E3779B97F4A7C15 ^ (i + 1)`; `MULTI`, `TX_N` × `SET key <32 × v>`, `EXEC`, pipelined; `max(20, TX_N)` keys drawn per transaction, the first `TX_N` used) and its writers (`MSET` of 2 keys, `<32 × w>`, seeds `0xD1B54A32D192ED03 ^ (i + 7)`). Added: a warm-up whose transactions are not counted, latencies over the measured window only, and a once-a-second series of completed transactions and writer operations with the worst latency of each second.

### 3.2 `paced`: offered against accepted

Each of `CONNS` connections has a fixed schedule, `CONNS / RATE` seconds apart (staggered across connections); a transaction is sent at its due time, or as soon as the previous one completes if it is late. Nothing is skipped, so **offered** (due) and **accepted** (completed) are counted separately; latency is measured both from the send and from the due time (so a backlog shows). Each transaction is `MULTI`, `TX_N` × `SET`, `EXEC` (100 `SET`s here, 32-byte values, as the original cell). Connection `c` writes only keys `i` with `i mod CONNS = c`, its transactions in sequence, and every value carries `(c, sequence number, member index)`, so the final value of every key is determined by the acknowledged transactions: the generator writes the expected keyspace (`load.expected`, one line per key).

A rate is **valid for comparing replica capacity** only if the primary accepted it: accepted/offered ≥ 0.99 over the measured window. A cell where the primary could not sustain the offered rate is reported but not used for the replica's capacity.

### 3.3 `verify`: real convergence

`verify` reads every key with pipelined `MGET`s and every TTL with `PTTL`, and reports `DBSIZE`, missing keys, mismatched values against the expected file, keys with a TTL, and an FNV-1a 64 digest of every key and value in key order. A run converges only if the primary matches the expected keyspace exactly, the replica's digest equals the primary's, and (with a replica AOF) the replica restarted alone from its own AOF matches as well. `contend` cells have no deterministic final state (many writers overwrite the same keys); they compare the replica's digest with the primary's after the drain. A negative check is in `raw/methodology/verify-negative.txt`: one tampered value, one deleted key and one TTL are each detected.

## 4. Placement

As the 6O-I cells: primary on CPU 0 (1 worker) or CPUs 0–2 (3 workers), replica on CPU 1 (1 worker), generator on CPUs 3–5. In the 3-worker cells the replica shares CPU 1 with a primary worker, as in the original cell; this is kept so the reproduction is exact, and its effect is noted where it matters. Data directories are on the HDD (`/home`), never on tmpfs, except `r3`'s tmpfs control. **`e6`** moves the replica to CPU 5 and the generator to CPUs 3–4, so that no primary worker shares the replica's CPU.

## 7. Limits

- **Foreign load.** The desktop session stays up. Net of both servers and the generator, the host's other CPU use was 1.2–2.0 CPUs during `e1`, `ex`, `r1` and `e5` reps 1–2, and about 0.4 CPUs from `e5` rep 3 onward (the drop coincides with excluding the bench directory from the desktop file indexer). Labels within a rep run within minutes of one another, so the paired ratios see the same regime. The quieter campaigns give the same ratios (`e1q`, foreign 0.39–0.43 CPU: P/H 0.938 transactions, 1.030 CPU per transaction; `et`'s default cell agrees; `e1`: 0.948, 1.033). Absolute values are not compared across campaigns.
- **Swap.** About 5 GiB of swap was in use throughout (desktop applications); `e1d` rep 2 saw a swap burst (`SwapFree` 3.4 → 2.2 GiB, I/O pressure 33%). It is recorded and its ratios agree with the other reps.
- **schedstat** sums the threads alive at each sample; a thread that exits between samples loses its time (Tokio's blocking-pool threads only).
- **perf stat** counts for `measure` seconds from the driver's own clock, a few hundred milliseconds from the generator's window.
- **The paced generator** keeps sending a late backlog after its window closes (up to 4.5 s in overloaded cells); the drain starts after it finishes.
- **INFO** calls by the sampler time out (2 s) on a stalled server; those seconds are missing from the series, and the summarizer's interpolation (used only at the window's two ends) spans them.
- **Disk reads** were not recorded before v7; an outside disk-busy episode (disk 81–96% busy at the same write rate, 04:08–04:21) overlapped `r2` rep 1 (review A round 2, N1).
- **btrfs `zstd`** compresses the synthetic AOF about 7×, so the disk results are specific to this host, filesystem and data.
- **Process hygiene:** the prefill and verify children are run synchronously, outside the driver's process groups; the replication port is checked free before a run but its listener's owner is not checked (review A L5).
- **Diag builds** carry instrumentation overhead. Diag v1 was unequal between 6O-H's per-frame path and 6O-I's per-group path, and its H runs are excluded from `e5`; v2 has no shared counters, and from `e7b` on every diag primary runs with its label's production replica. **Exception:** `r3`'s diag cell (`raof-2300-diag`) ran diag v1 on *both* nodes, so H's replica there times every frame (0.76 CPU, 332 µs per transaction against 300–314 in production): its stall and read-gap figures (RST §4) are compared within a build, not H against I and P (review A round 3, R3-9).
