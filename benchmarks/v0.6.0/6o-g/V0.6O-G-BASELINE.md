## G0: the defect on the baseline

`an_outside_reader_never_sees_a_transaction_part_way` (`RECACHED_PROBE_6OE_F1=1`), 10 runs on `25948a1`: **10 of 10 failed**, each with `MGET a b = [new, old]` (`raw/g0/f1-probe-on-25948a1.log`). The probe stops `MULTI SET a new SET b new EXEC` after its first queued write (`exec_pause`, between the commands' awaits) and reads from another connection.

The extended reproductions (GET of the first and of a later key, MGET, EXISTS, TYPE, STRLEN, borrowed reads, WebSocket reads, several readers, an unrelated writer) were written against the synchronous stop inside the write span, which only exists with 6O-G; on the baseline the same readers see the transaction part-way through the asynchronous gap between queued commands, as the F1 probe shows. They are permanent regression tests now (`V0.6O-G-CORRECTNESS-TESTS.md`).
