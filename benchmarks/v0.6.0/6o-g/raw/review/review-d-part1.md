## Review D (performance), Part 1: 49b26aa and the benchmark methodology

**Verdicts**
- **Commit 49b26aa: APPROVE WITH CHANGES.** The capped-store narrowing holds up: I found no way for a fitting queue to evict, refuse, sweep, roll back or touch a key outside its own stripes. One new Low defect is proven (D-1), and the design deviation needs to be written into the design and signed off (D-2).
- **Methodology: ACCEPT WITH CHANGES.** The pairing works and the per-rep ratios are consistent. But the in-process microbenchmark does not explain the native results, the load generator is unmeasured, and several cells the brief requires are missing or don't exercise what they claim to.

My pre-check and the test were in the same command, so I didn't wait — my mistake. Affected cells are rep 1, roughly 17:13:10–17:14:13Z:

- `mget-mset`, both labels.

Discard and rerun these. The load guard didn't catch it (pre-cell load 2.31), which is direct evidence for M-3. I ran nothing after that.

### What I verified
- **Fit-check soundness, by reading the code.** I traced every capped write path:
  - `run_write_gated`: no reservation inside the scope; `reserve_key_slots` needs nothing to be swept or evicted while count plus creations stays ≤ max; no rollback copy and no eviction loop while memory stays ≤ target (which is below limit).
  - Every outside party that could use up the headroom takes the gate first: gated writers, reserved writes (shared gate), the sweeper, the eviction tick.
  - Followers are excluded (`capped` is false), and `set_follower(true)` happens only at startup.
  - The server takes `lock_all_writes` for capped EXECs.
  - Every command `mutation_scope` classes ReadOnly really is read-only; `growth_bound` returns None for STORE, COPY, JSET and JMERGE; FLUSHDB is excluded.
- **Fit-check soundness, by randomized probe.** 20,000 seeds produced 11,927 fitting and 5,683 declined queues, across four eviction policies and both caps, with expired keys present and RENAME, SMOVE, duplicate-key MSET, HDEL, LPOP, EXPIRE and GETDEL included. Every fitting queue: no eviction, no capacity refusal, no key outside the queue changed, memory ≤ target, keys ≤ max, no in-scope assertion fired.
- **Boundary probe:** each write fits alone but the queue as a whole is declined, and memory fits exactly at the boundary and fails at boundary+1.
- **`hold_transaction` set-bit iteration:** correct and ascending.
- **Phase-2 early return:** equivalent to the old path. With no AOF, no replication, no watch, no WebSocket, no eviction and no PUBLISH, the old loop did nothing but fire the test hooks, which the early return keeps. `converge` still runs; `would_route` is false when no WebSocket is active; registration races are unchanged (`watched_after_write` handshake; replica attach waits on the all-write barrier).
- **Tests:** core-engine lib with test-hooks, 616 passed (plus the transaction tests and my probes).
- **Binary provenance:** gopt was built from 49b26aa with a clean tree; all binaries used the same rustc 1.98.0.
